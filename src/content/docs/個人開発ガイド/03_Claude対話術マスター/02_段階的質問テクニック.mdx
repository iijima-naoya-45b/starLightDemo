## 🎯 段階的質問テクニック：複雑な問題を分解して解決する技術

### 📝 段階的質問の定義

**ポケモンで例えると**: 段階的質問は、**「四天王に挑む前に、まずジムリーダーを倒していく戦略」**です。一度に全部やろうとしても無理——複雑な問題は、**「小さく分割して、1つずつ確実に解決する」**のが正解です。

段階的質問とは、大きな問題を小さなステップに分解し、順番に質問していく技術——Claudeとの対話を、**「連続した学習プロセス」**として捉えることで、より深い理解と質の高い解決策が得られます。

この記事は、**「段階的質問で複雑な問題を確実に解決する方法」**の完全ガイドです。

### 1. 🎯 段階的質問の「3つのメリット」

| メリット | 一度に全部聞く | 段階的に質問 |
|---------|------------|-----------|
| **理解の深さ** | 浅い（全体を流す） | 深い（各ステップを理解） |
| **回答の質** | 汎用的・抽象的 | 具体的・実践的 |
| **応用力** | 低い（丸暗記） | 高い（原理を理解） |

**ポケモン版**: **「レベル5ずつ上げる vs 一気にレベル100」**——段階的な方が、確実に強くなる。

### 2. 🚀 基本パターン：「3段階質問法」

#### ステップ1: 概要を掴む

**最初の質問**:
```
「Reactのパフォーマンス最適化について、全体像を教えてください。

以下の観点で概要を説明してください：
- なぜ最適化が必要なのか
- 主な最適化手法（5つ程度）
- 各手法の難易度

初心者でもわかるように、概要レベルで構いません。」
```

**効果**: 全体像が見えて、次に何を深掘りすべきかわかる

#### ステップ2: 詳細を深掘りする

**2つ目の質問**:
```
「先ほどの5つの最適化手法の中で、「メモ化」について詳しく教えてください。

以下を含めて説明してください：
- メモ化とは何か
- いつ使うべきか
- useMemoとuseCallbackの違い
- 具体的なコード例（Before/After）
- よくある間違い」
```

**効果**: 1つのトピックを深く理解できる

#### ステップ3: 実践に落とし込む

**3つ目の質問**:
```
「学んだメモ化の技術を、以下のコンポーネントに適用してください：

[実際のコード]

どこをどう最適化すべきか、具体的な修正案を提示してください。」
```

**効果**: 知識が実践的なスキルに変わる

**ポケモン版**: **「技の存在を知る → 使い方を学ぶ → 実戦で使う」**——段階的に習得。

### 3. 🔥 応用パターン1: 「Why→What→How」質問法

#### フェーズ1: Why（なぜ）

```
「なぜTypeScriptを使うべきなのですか？

以下の観点から説明してください：
- JavaScriptの何が問題なのか
- TypeScriptはその問題をどう解決するのか
- 導入コストに見合うメリットがあるのか」
```

**目的**: 動機と背景を理解

#### フェーズ2: What（何を）

```
「TypeScriptの主要な機能を教えてください。

特に以下を重点的に：
- 型システムの基本
- インターフェースとタイプの違い
- ジェネリクスの概念
- ユーティリティ型の使い方」
```

**目的**: 基本的な機能を網羅

#### フェーズ3: How（どのように）

```
「既存のJavaScriptプロジェクトをTypeScriptに移行する手順を教えてください。

以下を含めて：
- 段階的な移行戦略
- 最初に型をつけるべきファイル
- よくある移行の壁と解決策
- チーム全体への展開方法」
```

**目的**: 実践的な方法を習得

**ポケモン版**: **「なぜ進化するのか → 何が変わるのか → どう進化させるか」**——原理から実践へ。

### 4. ⚡ 応用パターン2: 「広く浅く→狭く深く」質問法

#### フェーズ1: 広く浅く（オプションの洗い出し）

```
「Webアプリケーションの状態管理ライブラリを選定したいです。

候補となるライブラリを10個挙げて、それぞれを1行で説明してください。」
```

**効果**: 選択肢の全体像を把握

#### フェーズ2: 絞り込み（比較）

```
「先ほどの10個の中から、以下の条件に合うものを3つに絞ってください：

【条件】
- 学習コストが低い
- TypeScript対応
- 小規模プロジェクト向け
- メンテナンスが活発

3つについて、詳しく比較してください。」
```

**効果**: 候補を絞り込める

#### フェーズ3: 深掘り（詳細調査）

```
「3つの中で、Zustandについて詳しく教えてください：

- 基本的な使い方（コード例）
- Reduxとの違い
- メリット・デメリット
- 実際のプロジェクトでの採用事例
- 学習リソース」
```

**効果**: 最終決定に必要な詳細情報を取得

**ポケモン版**: **「全ポケモンを見る → タイプで絞る → 最強の1匹を選ぶ」**——選択肢から最適解へ。

### 5. 📊 応用パターン3: 「理論→実例→応用」質問法

#### フェーズ1: 理論（概念の理解）

```
「Reactのレンダリング最適化における「再レンダリング」の仕組みを説明してください。

以下を含めて：
- 再レンダリングとは何か
- いつ発生するのか
- なぜパフォーマンス問題になるのか
- どうやって検出するのか

技術的な詳細まで踏み込んで説明してください。」
```

**目的**: 原理原則を理解

#### フェーズ2: 実例（具体例で学ぶ）

```
「再レンダリングの問題が起きている具体例を3つ示してください：

各例について：
- 問題のあるコード
- 何が問題なのか
- どう修正すべきか（コード例）
- なぜその修正で解決するのか

実際によくあるパターンを選んでください。」
```

**目的**: 実践的なパターンを学習

#### フェーズ3: 応用（自分のコードに適用）

```
「学んだ知識を、以下の私のコードに適用してください：

[実際のコード]

以下を分析してください：
- 再レンダリングの問題はあるか
- あれば、どこが問題か
- 具体的な修正案
- 修正後の期待される効果

実際に修正したコードも提示してください。」
```

**目的**: 知識を実践に変換

**ポケモン版**: **「技の理論 → 実戦動画 → 自分で使う」**——理解から実践へ。

### 6. 🎯 応用パターン4: 「失敗から学ぶ」質問法

#### ステップ1: 失敗を分析

```
「以下のコードで、パフォーマンスが悪いです：

[コード]

症状：
- 画面が重い
- スクロールがカクつく
- CPU使用率が高い

何が問題なのか、考えられる原因を5つ挙げてください。」
```

#### ステップ2: 原因を特定

```
「5つの原因の中で、最も可能性が高いものを特定してください。

以下の追加情報を提供します：
- [追加のコードや症状]

可能性の高い順に並べ替え、それぞれの検証方法を教えてください。」
```

#### ステップ3: 解決策を実装

```
「最も可能性の高い原因「〇〇」について、解決策を実装してください：

- 修正後のコード
- なぜこの修正で解決するのか
- 副作用はないか
- 他に注意すべき点

実際に動くコードで提示してください。」
```

#### ステップ4: 再発防止

```
「今回の失敗を繰り返さないために：

- なぜこの問題が起きたのか（根本原因）
- 同じ失敗を避けるためのチェックリスト
- 将来の設計で気をつけること
- チームで共有すべきこと

ドキュメントとしてまとめてください。」
```

**ポケモン版**: **「負けた理由を分析 → 対策を立てる → 次は勝つ」**——失敗から学ぶ。

### 7. 🚨 段階的質問の「5つのコツ」

#### コツ1: 前の回答を参照する

```
悪い例：
質問1: 「Reactとは？」
質問2: 「Vueとは？」 ← 繋がりがない

良い例：
質問1: 「Reactとは？」
質問2: 「先ほど説明してくれたReactと、Vueの違いは何ですか？」 ← 前の回答を活用
```

**効果**: 会話の文脈が繋がる

#### コツ2: 理解度を確認する

```
「先ほどの説明で、〇〇の部分がまだ理解できていません。
もう少し詳しく、初心者向けに説明してください。

特に、以下が理解できませんでした：
- [具体的な部分1]
- [具体的な部分2]」
```

**効果**: わからない部分を明確にできる

#### コツ3: 次のステップを聞く

```
「〇〇について理解できました。

次に学ぶべきことは何ですか？
学習の順番も教えてください。」
```

**効果**: 学習の道筋が見える

#### コツ4: 具体例を求める

```
「抽象的な説明はわかりました。

具体的な例を3つ示してください。
実際のコードで見せてもらえると理解しやすいです。」
```

**効果**: 抽象から具体へ

#### コツ5: 応用を試す

```
「学んだことを応用して、以下のケースではどうすべきか教えてください：

[新しいケース]

今まで学んだ知識を使って、解決策を提案してください。」
```

**効果**: 知識が応用力に変わる

**ポケモン版**: **「段階的にレベルアップ」**——焦らず、確実に成長。

### 8. 📝 段階的質問のテンプレート集

#### テンプレート1: 新しい技術を学ぶ

```
ステップ1: 全体像
「[技術名]について、初心者向けに全体像を教えてください」

ステップ2: 基本
「[技術名]の基本的な使い方を、コード例で示してください」

ステップ3: 応用
「[技術名]を使って、[やりたいこと]を実装してください」

ステップ4: ベストプラクティス
「[技術名]を使う際の、ベストプラクティスとアンチパターンを教えてください」
```

#### テンプレート2: 問題を解決する

```
ステップ1: 問題の整理
「[症状]という問題が起きています。考えられる原因を列挙してください」

ステップ2: 原因の特定
「原因候補の中から、最も可能性の高いものを特定してください」

ステップ3: 解決策の提案
「特定した原因に対する、解決策を3つ提案してください」

ステップ4: 実装
「最も適切な解決策を実装してください」
```

#### テンプレート3: 設計を決める

```
ステップ1: 要件の整理
「[やりたいこと]を実現するための、要件を整理してください」

ステップ2: 選択肢の列挙
「要件を満たす設計アプローチを、5つ提案してください」

ステップ3: 比較
「5つのアプローチを比較し、それぞれのメリット・デメリットを示してください」

ステップ4: 決定
「[条件]を考慮すると、どのアプローチが最適ですか？理由も含めて教えてください」
```

**ポケモン版**: **「攻略チャート」**——順番に進めば、確実にクリア。

### 9. 🎓 まとめ：段階的質問の心得

**段階的質問の本質**:
- 複雑な問題を分解
- 1つずつ確実に理解
- 前の回答を活用

**4つの基本パターン**:
1. 概要 → 詳細 → 実践
2. Why → What → How
3. 広く浅く → 狭く深く
4. 理論 → 実例 → 応用

**最後に**:
段階的質問は、Claudeとの対話を「学習プロセス」に変える技術——焦らず、1つずつ積み上げていけば、確実に理解できます！

**ポケモン版**: **「レベル1から着実に育てる」**——段階的成長が、最強への道。
