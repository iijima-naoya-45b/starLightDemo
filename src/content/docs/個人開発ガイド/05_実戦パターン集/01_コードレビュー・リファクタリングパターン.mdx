## 🔍 実戦で使えるコードレビュー・リファクタリングパターン

### 🎯 コードレビューの「5つの実戦パターン」

#### パターン1: セキュリティチェック

```
「以下のコードのセキュリティ脆弱性をチェックしてください：

[コード]

【チェック項目】
- SQLインジェクション
- XSS
- CSRF
- 認証・認可の漏れ
- 入力バリデーション
- 機密情報の露出

OWASP Top 10を基準に、優先度付きで指摘してください。」
```

#### パターン2: パフォーマンス分析

```
「以下のコードのパフォーマンス問題を分析してください：

[コード]

【分析観点】
- 計算量（Big O記法）
- メモリ使用量
- ボトルネック
- 最適化の余地
- トレードオフ

具体的な改善案とその効果を数値で示してください。」
```

#### パターン3: 可読性チェック

```
「以下のコードの可読性を評価してください：

[コード]

【評価基準】
- 命名の適切性
- 関数の責務
- コメントの質
- ネストの深さ
- マジックナンバー

10点満点で評価し、改善案を提示してください。」
```

**ポケモン版**: **「技の効果を多角的に分析」**——あらゆる観点でチェック。

### 2. 🔥 リファクタリングの「5つの実戦パターン」

#### パターン1: 関数分割

```
「以下の長い関数を、適切なサイズに分割してください：

[長い関数]

【分割方針】
- 単一責任の原則
- 再利用性を考慮
- テストしやすさを重視

Before/Afterで示し、分割の意図も説明してください。」
```

#### パターン2: DRY原則の適用

```
「以下のコードの重複を排除してください：

[重複のあるコード]

【リファクタリング方針】
- 共通処理の抽出
- 適切な抽象化レベル
- 過度な抽象化は避ける

共通化する部分としない部分を明確に説明してください。」
```

#### パターン3: デザインパターンの適用

```
「以下のコードに適したデザインパターンを提案してください：

[コード]

【考慮事項】
- 現在の問題点
- 適用可能なパターン3つ
- 各パターンのメリット・デメリット
- 推奨パターン

実装例も含めて説明してください。」
```

**ポケモン版**: **「技の構成を最適化」**——より強い形に進化。

### 3. 📊 実例：レビュー&リファクタリングの完全フロー

**ステップ1: 初回レビュー**
```
「PRのコードを初回レビューしてください：

[差分]

【確認事項】
- 機能要件を満たしているか
- テストは十分か
- ドキュメントは更新されているか

大まかな方向性の問題を指摘してください。」
```

**ステップ2: 詳細レビュー**
```
「方向性OKです。詳細レビューをお願いします：

【重点チェック】
- セキュリティ
- パフォーマンス
- 可読性
- エッジケース

コード品質を徹底的にチェックしてください。」
```

**ステップ3: リファクタリング提案**
```
「レビュー指摘を受けて、リファクタリング案を提示してください：

【改善ポイント】
[指摘された問題]

優先度順に、具体的な修正コードを示してください。」
```

**ポケモン版**: **「段階的に育成」**——確実にレベルアップ。

### 4. 🎓 まとめ

**レビューの5パターン**:
1. セキュリティチェック
2. パフォーマンス分析
3. 可読性チェック
4. アーキテクチャ確認
5. テスト網羅性

**リファクタリングの5パターン**:
1. 関数分割
2. DRY原則
3. デザインパターン
4. 型安全性向上
5. エラーハンドリング改善

**最後に**:
これらのパターンを使えば、コードレビューもリファクタリングも効率的——高品質なコードを量産しましょう！
