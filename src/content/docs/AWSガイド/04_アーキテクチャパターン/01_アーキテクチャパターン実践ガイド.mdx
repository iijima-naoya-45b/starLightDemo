## AWS アーキテクチャパターン 実践ガイド


**ポケモンで例えると**: AWSを理解することは、新しい「わざ」を覚えるようなもの——使いこなせば、より強力な開発者になれます。

実務とAWS試験で頻出のアーキテクチャパターンをまとめました。SAA/SAP試験では、これらのパターンを理解し、適切に選択できることが求められます。

### 3層Webアプリケーション

#### 1. 基本構成（高可用性）

```yaml
構成:
  Web層:
    - Application Load Balancer (マルチAZ)
    - EC2 Auto Scaling Group
    - CloudFront (CDN)
  
  アプリケーション層:
    - EC2 Auto Scaling Group (プライベートサブネット)
    - Lambda (サーバーレスオプション)
  
  データベース層:
    - RDS Multi-AZ
    - ElastiCache (Redis/Memcached)
    - S3 (静的コンテンツ)

特徴:
  - 99.99%の可用性
  - 自動スケーリング
  - マルチAZ配置
  - 障害時の自動フェイルオーバー
```

#### 2. グローバル展開

```yaml
マルチリージョン構成:
  プライマリリージョン: ap-northeast-1
    - Application Stack
    - Aurora Global Database (Primary)
    - S3 Cross-Region Replication
  
  セカンダリリージョン: us-east-1
    - Standby Application Stack
    - Aurora Global Database (Secondary)
    - S3 Replica
  
  グローバルサービス:
    - Route 53:
        - Geolocation Routing (地理的ルーティング)
        - Health Checks (ヘルスチェック)
        - Failover Routing (フェイルオーバー)
    - CloudFront:
        - Origin Group (オリジングループ)
        - Cache Optimization

RPO: 1秒
RTO: 1分
```

### ディザスタリカバリ

#### 1. バックアップと復元

```yaml
構成:
  - AWS Backup (一元管理)
  - Cross-Region Backup
  - Point-in-Time Recovery

特徴:
  RPO: 1時間〜24時間
  RTO: 数時間〜数日
  コスト: 最低

適用:
  - 非クリティカルシステム
  - コスト重視
```

#### 2. パイロットライト

```yaml
構成:
  プライマリリージョン:
    - フル構成
  
  DRリージョン:
    - コアサービスのみ稼働
    - RDS (最小スペック)
    - EC2 AMI準備
    - Auto Scaling設定（Min=0）

災害時:
  1. RDSスケールアップ
  2. EC2 Auto Scaling起動
  3. Route 53フェイルオーバー

特徴:
  RPO: 数分
  RTO: 10分〜30分
  コスト: 中

適用:
  - ビジネスクリティカル
  - コストとRTOのバランス
```

#### 3. ウォームスタンバイ

```yaml
構成:
  プライマリリージョン:
    - フル構成
  
  DRリージョン:
    - 縮小版が常時稼働
    - RDS (小スペック、レプリケーション)
    - EC2 (最小台数)

災害時:
  1. Auto Scalingでスケールアウト
  2. RDSスケールアップ
  3. Route 53フェイルオーバー

特徴:
  RPO: 数秒
  RTO: 数分
  コスト: 中〜高

適用:
  - ミッションクリティカル
  - 短いRTO要件
```

#### 4. マルチサイトアクティブ/アクティブ

```yaml
構成:
  両リージョン:
    - フル構成で稼働
    - Aurora Global Database
    - DynamoDB Global Tables
    - S3 Cross-Region Replication

ルーティング:
  - Route 53 Geolocation Routing
  - CloudFront (グローバル配信)
  - Global Accelerator

特徴:
  RPO: 0秒
  RTO: 0秒（自動フェイルオーバー）
  コスト: 最高

適用:
  - ゼロダウンタイム要件

```

### まとめ

**アーキテクチャパターンの選択基準:**

```yaml
可用性要件:
  - 99.9%: シングルAZ
  - 99.99%: マルチAZ
  - 99.999%: マルチリージョン

パフォーマンス:
  - 低レイテンシー: CloudFront, ElastiCache, DynamoDB
  - 高スループット: Kinesis, DynamoDB, Aurora

コスト:
  - 低コスト: Spot, Lambda, S3
  - 予測可能: Reserved, Savings Plans

スケーラビリティ:
  - 自動: Lambda, DynamoDB, Fargate
  - 手動: EC2, RDS
```

**SAA/SAP試験での重要ポイント:**

1. **Well-Architected Framework**: 5つの柱（運用、セキュリティ、信頼性、パフォーマンス、コスト）
2. **DR戦略**: RPO/RTOに応じたパターン選択
3. **マイクロサービス**: サービス間通信、データ整合性
4. **ハイブリッド**: Direct Connect、Storage Gateway
5. **コスト最適化**: Spot、Reserved、Savings Plans

適切なアーキテクチャパターンの選択により、ビジネス要件に最適なシステムを構築できます。
