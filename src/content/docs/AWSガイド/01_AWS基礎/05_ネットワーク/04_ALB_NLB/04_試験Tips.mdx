## ALB/NLB 試験Tips (SAA/SAP)

### 頻出トピック

#### 1. ALB vs NLB選択

```yaml
ALB:
  レイヤー: 7（アプリケーション）
  プロトコル: HTTP/HTTPS
  機能: パスルーティング、認証、Lambda統合
  用途: Webアプリ、マイクロサービス
  レイテンシー: ミリ秒

NLB:
  レイヤー: 4（トランスポート）
  プロトコル: TCP/UDP/TLS
  機能: 静的IP、超低レイテンシー
  用途: 高パフォーマンス、TCP/UDP
  レイテンシー: マイクロ秒

頻出:
  Q: 静的IPアドレス必要
  A: NLB
  
  Q: パスベースルーティング
  A: ALB
  
  Q: 最低レイテンシー要求
  A: NLB
```

#### 2. ターゲット種類

```yaml
ALB:
  - EC2インスタンス
  - IPアドレス（オンプレミス可）
  - Lambda関数
  - ECSタスク

NLB:
  - EC2インスタンス
  - IPアドレス
  - ALB（!）
  - ECSタスク
```

#### 3. Sticky Session（セッション維持）

```yaml
ALB:
  - Cookie ベース
  - 持続時間: 1秒 〜 7日
  - アプリケーションCookie
  - ALB生成Cookie

頻出:
  Q: ユーザーセッション維持
  A: Sticky Session有効化
```

### 頻出シナリオ

#### シナリオ1: マイクロサービス

```
要件: /api/users, /api/ordersで異なるサービスへルーティング
解答: ALB + パスベースルーティング

設定:
  /api/users → Users ターゲットグループ
  /api/orders → Orders ターゲットグループ
```

#### シナリオ2: 静的IP必要

```
要件: ホワイトリスト登録のため静的IP必要
解答: NLB + Elastic IP

ポイント:
✓ NLBは静的IP割り当て可能
✓ Elastic IP指定可能
```

#### シナリオ3: HTTPS終端

```
要件: EC2でSSL処理負荷削減
解答: ALB + ACM証明書

ポイント:
✓ ALBでSSL終端
✓ バックエンドはHTTP
✓ ACM証明書無料
```

#### シナリオ4: クロスゾーン負荷分散

```
要件: AZ間で均等に負荷分散
解答: クロスゾーン負荷分散有効化

ALB: デフォルトで有効（無料）
NLB: デフォルトで無効（有料）
```

### よくある間違い

```yaml
× 誤り: NLBでパスルーティング
○ 正解: パスルーティングはALBのみ

× 誤り: ALBで静的IP
○ 正解: NLBで静的IP

× 誤り: NLBでLambda統合
○ 正解: Lambda統合はALBのみ

× 誤り: セキュリティグループをNLBターゲットに適用不要
○ 正解: NLBはクライアントIP保持、ターゲットSG要設定
```
