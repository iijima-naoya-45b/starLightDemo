## Elastic Load Balancing (ELB) とは？


**ポケモンで例えると**: AWSを理解することは、新しい「わざ」を覚えるようなもの——使いこなせば、より強力な開発者になれます。

ELBは、トラフィックを複数のターゲットに分散するマネージド型ロードバランサーです。ALB、NLB、CLB（Classic Load Balancer）の3種類があります。

### ロードバランサー種類

#### 1. ALB（Application Load Balancer）

```yaml
OSI層: レイヤー7（アプリケーション）
プロトコル: HTTP, HTTPS, WebSocket

特徴:
  - パスベースルーティング
  - ホストベースルーティング
  - HTTPヘッダールーティング
  - Lambda統合
  - 固定レスポンス
  - リダイレクト

ターゲット:
  - EC2インスタンス
  - IPアドレス
  - Lambda関数
  - ECSタスク

用途: Webアプリ、マイクロサービス、コンテナ
```

#### 2. NLB（Network Load Balancer）

```yaml
OSI層: レイヤー4（トランスポート）
プロトコル: TCP, UDP, TLS

特徴:
  - 超低レイテンシー（マイクロ秒）
  - 静的IPアドレス
  - Elastic IP割り当て可能
  - 数百万リクエスト/秒
  - クライアントIP保持

ターゲット:
  - EC2インスタンス
  - IPアドレス
  - ALB
  - ECSタスク

用途: 高パフォーマンス、TCP/UDP、静的IP必要
```

#### 3. CLB（Classic Load Balancer）

```yaml
OSI層: レイヤー4/7
非推奨: 新規作成推奨しない
レガシー: EC2-Classic対応
```

### ALB主要機能

#### ターゲットグループ

```yaml
概要:
  - ルーティング先の論理グループ
  - ヘルスチェック設定
  - 複数ターゲットグループ可能

設定:
  プロトコル: HTTP, HTTPS
  ポート: 任意
  ヘルスチェックパス: /health
  正常判定: 2回連続成功
  異常判定: 2回連続失敗
```

#### リスナールール

```yaml
条件:
  - パスパターン: /api/*
  - ホストヘッダー: example.com
  - HTTPヘッダー: User-Agent
  - HTTPメソッド: GET, POST
  - クエリ文字列: ?id=123
  - 送信元IP: 192.0.2.0/24

アクション:
  - forward: ターゲットグループへ転送
  - redirect: リダイレクト
  - fixed-response: 固定レスポンス
  - authenticate-oidc: 認証
```

### セキュリティ

```yaml
HTTPS:
  - SSL/TLS終端
  - ACM証明書統合
  - SNI対応（複数証明書）

セキュリティグループ:
  - インバウンド: 80, 443
  - アウトバウンド: ターゲットポート

WAF統合:
  - DDoS対策
  - アプリケーション保護
```

### まとめ

**ALB/NLBの重要ポイント:**
- ALB: HTTP/HTTPS、パスルーティング
- NLB: TCP/UDP、低レイテンシー、静的IP
- ヘルスチェックによる自動切替
- マルチAZ配置で高可用性
- Auto Scalingと連携
