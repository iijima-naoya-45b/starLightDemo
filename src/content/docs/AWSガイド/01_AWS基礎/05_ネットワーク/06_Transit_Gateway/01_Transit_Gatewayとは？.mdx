## AWS Transit Gateway とは？

AWS Transit Gateway は、複数のVPC、オンプレミスネットワーク、リモートオフィスを単一のゲートウェイで接続できるネットワークハブサービスです。

### 基本概念

#### Transit Gatewayの役割

```yaml
主要機能:
  - ネットワークハブ: 複数VPC・オンプレミスを中央集約
  - スケーラビリティ: 最大5,000のVPC接続
  - 簡素化: メッシュ型接続の複雑さを解消
  - 柔軟なルーティング: 複数のルートテーブル対応
  - トランジット接続: 推移的ルーティング対応

従来の課題解決:
  VPC Peering:
    - N個のVPCで N(N-1)/2 の接続が必要
    - 管理が複雑
    - スケールしない
  
  Transit Gateway:
    - N個のVPCでN個の接続のみ
    - 中央集約管理
    - 簡単にスケール
```

#### Transit Gatewayのメリット

```yaml
運用面:
  - 接続の簡素化: ハブアンドスポークアーキテクチャ
  - 一元管理: 単一ポイントでのルーティング管理
  - 自動フェイルオーバー: 高可用性の自動確保

技術面:
  - 帯域幅: 最大50Gbps/アタッチメント
  - マルチキャスト: マルチキャストトラフィック対応
  - Equal Cost Multi-Path: ECMP対応
  - ルート分離: 複数ルートテーブルで環境分離

拡張性:
  - クロスリージョンPeering: リージョン間接続
  - VPN接続: オンプレミス統合
  - Direct Connect接続: 専用線統合
  - SD-WAN統合: Software-Defined WAN
```

### Transit Gatewayの主要コンポーネント

#### 1. Transit Gateway本体

```yaml
特徴:
  - リージョンリソース
  - 複数AZで自動冗長化
  - 拡張可能な帯域幅
  - IPv4/IPv6対応

設定:
  ASN (Autonomous System Number):
    - BGPルーティング用
    - デフォルト: 64512
    - カスタマイズ可能
  
  CIDRブロック:
    - VPC間ルーティング用
    - オプション設定
```

#### 2. アタッチメント (Attachments)

```yaml
タイプ:
  VPC Attachment:
    - VPCをTransit Gatewayに接続
    - サブネット単位で接続（各AZに1つ推奨）
    - ENI自動作成
  
  VPN Attachment:
    - Site-to-Site VPN接続
    - オンプレミスネットワーク接続
    - IPsec暗号化
  
  Direct Connect Gateway Attachment:
    - Direct Connect経由接続
    - 低レイテンシー、高帯域
    - 専用線接続
  
  Peering Attachment:
    - 異なるリージョンのTransit Gateway間接続
    - クロスリージョン通信
    - クロスアカウント対応

設定ポイント:
  - アタッチメントごとに課金
  - ルートテーブル関連付け必要
  - VPCアタッチメントはAZごとに推奨
```

#### 3. ルートテーブル (Route Tables)

```yaml
特徴:
  - アタッチメントごとに関連付け
  - 複数のルートテーブル作成可能
  - 環境分離（本番/開発など）

ルートタイプ:
  Static Route:
    - 手動設定
    - 固定ルート
  
  Propagated Route:
    - 自動伝播
    - VPC CIDR自動追加
    - VPN BGPルート伝播

設定例:
  本番環境ルートテーブル:
    - 本番VPCアタッチメント関連付け
    - オンプレミスへのルート
    - 他の本番VPCへのルート
  
  開発環境ルートテーブル:
    - 開発VPCアタッチメント関連付け
    - 限定的なルート
    - 本番環境へのアクセス制限
```

#### 4. ルート伝播 (Route Propagation)

```yaml
概要:
  - VPC CIDRの自動伝播
  - BGPルートの自動学習
  - 手動設定不要

動作:
  VPC Attachment:
    - VPC CIDRを自動的にルートテーブルに追加
    - VPC追加時も自動更新
  
  VPN/Direct Connect:
    - BGPで学習したルートを伝播
    - オンプレミスルート自動追加

設定:
  - ルートテーブルごとに有効/無効
  - 細かい制御が可能
```

### Transit Gatewayのアーキテクチャ

#### ハブアンドスポーク構成

```yaml
構成:
  Hub (Transit Gateway):
    - 中央ハブとして機能
    - 全てのトラフィックが通過
  
  Spoke (VPC/オンプレミス):
    - Transit Gatewayに接続
    - 他のSpokeと通信

メリット:
  - 接続数削減: N個でなくN個の接続
  - 管理簡素化: 中央集約
  - スケーラビリティ: 容易な拡張
  - セキュリティ: 一元的な制御

使用例:
  本番VPC1 \
  本番VPC2  -- Transit Gateway -- オンプレミス
  開発VPC1 /                  \
  開発VPC2                     Direct Connect
```

#### マルチリージョン構成

```yaml
構成:
  ap-northeast-1:
    - Transit Gateway 1
    - 複数VPC接続
  
  us-east-1:
    - Transit Gateway 2
    - 複数VPC接続
  
  接続:
    - Transit Gateway Peering
    - クロスリージョン通信

メリット:
  - グローバル展開
  - リージョン間プライベート通信
  - DR (Disaster Recovery)
  - レイテンシー最適化
```

### Transit Gatewayのネットワーク機能

#### 1. Equal Cost Multi-Path (ECMP)

```yaml
概要:
  - 複数の等コストパス使用
  - 帯域幅集約
  - 冗長性向上

使用例:
  VPN接続:
    - 複数のVPNトンネル
    - 最大50Gbps (1.25Gbps × 最大40トンネル)
    - 自動負荷分散

Direct Connect:
    - 複数のDirect Connect接続
    - 帯域幅合算
    - 自動フェイルオーバー
```

#### 2. マルチキャスト

```yaml
概要:
  - 1対多の通信
  - 帯域効率的
  - リアルタイムデータ配信

使用例:
  - ビデオストリーミング
  - 株価データ配信
  - ソフトウェア配布

設定:
  - マルチキャストドメイン作成
  - VPCアタッチメント関連付け
  - IGMPプロトコル使用
```

#### 3. Network Manager

```yaml
概要:
  - グローバルネットワーク可視化
  - 集中管理ツール
  - モニタリング・トラブルシューティング

機能:
  - トポロジー表示
  - メトリクス監視
  - イベント通知
  - ルート分析

対応範囲:
  - Transit Gateway
  - VPC
  - Direct Connect
  - VPN
  - オンプレミスデバイス
```

### Transit Gatewayの制限

```yaml
デフォルト制限:
  - Transit Gateway per リージョン: 5 (上限緩和可能)
  - VPC Attachments per Transit Gateway: 5,000
  - VPN Attachments per Transit Gateway: 10
  - Direct Connect Gateway Attachments: 20
  - Peering Attachments: 50
  - Route Tables per Transit Gateway: 20
  - Routes per Route Table: 10,000

帯域幅:
  - 最大帯域: 50 Gbps/アタッチメント
  - ECMP使用時: 複数パスで増加可能
  - バースト対応

パケット:
  - 最大MTU: 8500バイト
  - パケット/秒: 数百万pps
```

### VPC Peering との比較

```yaml
VPC Peering:
  適用シーン:
    - 2-3個のVPC接続
    - シンプルな構成
    - コスト重視
  
  コスト:
    - 接続自体は無料
    - データ転送: $0.01/GB (クロスAZ)
  
  制限:
    - 推移的ルーティング不可
    - CIDR重複不可
    - 管理が複雑化（多数接続時）

Transit Gateway:
  適用シーン:
    - 3個以上のVPC接続
    - オンプレミス統合
    - 複雑なルーティング
    - 将来の拡張性重視
  
  コスト:
    - アタッチメント: $0.05/時間
    - データ処理: $0.02/GB
  
  メリット:
    - 推移的ルーティング対応
    - 中央集約管理
    - スケーラブル
    - 柔軟なルーティング制御

損益分岐点:
  - 3-4個のVPC以上でTransit Gatewayが効率的
  - 管理容易性を考慮すると2-3個でも検討価値あり
```

### Transit Gateway vs その他の接続方法

```yaml
VPC Peering:
  - 1対1接続
  - 推移的ルーティング不可
  - コスト低

Transit Gateway:
  - ハブアンドスポーク
  - 推移的ルーティング対応
  - 中規模以上で効率的

VPN:
  - オンプレミス接続
  - 暗号化通信
  - 帯域制限あり

Direct Connect:
  - オンプレミス専用線
  - 高帯域、低レイテンシー
  - コスト高

PrivateLink:
  - サービス単位の接続
  - プライバシー保護
  - 特定ユースケース向け
```

### まとめ

**Transit Gatewayの重要ポイント:**

- **ネットワークハブ**: 複数VPC・オンプレミスを中央集約
- **スケーラビリティ**: 最大5,000 VPC接続対応
- **柔軟なルーティング**: 複数ルートテーブルで環境分離
- **グローバル展開**: クロスリージョンPeering対応
- **高可用性**: マルチAZ自動冗長化
- **コスト**: 3個以上のVPC接続で効率的

Transit Gatewayは、複数のVPCやオンプレミスネットワークを統合する大規模ネットワークの構築に最適なサービスです。
