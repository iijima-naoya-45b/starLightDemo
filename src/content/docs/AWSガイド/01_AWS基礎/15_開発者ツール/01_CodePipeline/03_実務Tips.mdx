## CodePipeline 実務Tips

### AWS CLI

```bash
# パイプライン作成
aws codepipeline create-pipeline \
  --cli-input-json file://pipeline.json

# パイプライン一覧
aws codepipeline list-pipelines

# パイプライン詳細取得
aws codepipeline get-pipeline --name my-pipeline

# パイプライン実行
aws codepipeline start-pipeline-execution \
  --name my-pipeline

# 実行状態確認
aws codepipeline get-pipeline-state --name my-pipeline

# パイプライン更新
aws codepipeline update-pipeline \
  --cli-input-json file://pipeline-updated.json

# パイプライン削除
aws codepipeline delete-pipeline --name my-pipeline

# 承認アクション
aws codepipeline put-approval-result \
  --pipeline-name my-pipeline \
  --stage-name Approval \
  --action-name ManualApproval \
  --result status=Approved,summary="Looks good" \
  --token <token-from-sns>
```

### ベストプラクティス

```yaml
設計:
  - ステージ名は明確に（Source、Build、Test、Deploy）
  - 環境ごとにパイプライン分離
  - アーティファクトの暗号化

セキュリティ:
  - IAMロール最小権限
  - Secrets Manager/Parameter Storeで認証情報管理
  - GitHub Personal Tokenは使わずCodeStar接続使用
  - アーティファクトS3バケットの暗号化

運用:
  - 承認ゲート設定（本番デプロイ前）
  - SNS通知統合
  - CloudWatch Eventsでモニタリング
  - 失敗時のロールバック計画

モニタリング:
  - CloudWatch Logsで実行ログ確認
  - CloudWatch Eventsでパイプライン状態変更検知
  - ダッシュボード作成

コスト最適化:
  - 不要なパイプラインは削除
  - アーティファクトのライフサイクル設定
  - 開発環境は必要時のみ実行
```

### トラブルシューティング

```yaml
よくある問題:
  アーティファクトが見つからない:
    - outputArtifacts/inputArtifacts名の一致確認
    - S3バケット存在確認

  IAM権限エラー:
    - CodePipelineサービスロール確認
    - クロスアカウント時の信頼関係
    - S3バケットポリシー

  GitHub連携失敗:
    - CodeStar接続の承認状態確認
    - リポジトリアクセス権限
    - ブランチ名の正確性

  デプロイ失敗:
    - ターゲット環境の状態確認
    - アプリケーション/デプロイグループ存在確認
    - CloudWatch Logsで詳細確認
```
