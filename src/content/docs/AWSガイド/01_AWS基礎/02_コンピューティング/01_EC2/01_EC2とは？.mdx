## Amazon EC2 (Elastic Compute Cloud) とは？

Amazon EC2は、AWSクラウド上で仮想サーバー（インスタンス）を起動できるコンピューティングサービスです。
この資料は、**理想論ではなく、実務で使える実践的なEC2の運用方法**を解説します。

### なぜEC2が必要か

#### 問題のある構成（オンプレミス/自前サーバー管理）

**問題のある状況:**

```
問題のある構成:
- 物理サーバーの調達に数週間〜数ヶ月かかる
- 初期投資（ハードウェア購入費）が高額
- ピーク時に合わせた過剰なキャパシティ確保が必要
- サーバーの保守・運用コストが継続的に発生
- スケールアップ/スケールダウンが困難
- 障害時の復旧に時間がかかる
- データセンターの物理的な管理が必要

影響:
- ビジネスのスピードが遅くなる
- 無駄なコストが発生する
- リソースの柔軟な調整ができない
- 運用負荷が高い
- グローバル展開が困難
```

**解決: EC2による柔軟なコンピューティングリソース**

```
解決策:
- 数分でサーバーを起動できる
- 従量課金制で無駄なコストを削減
- 必要に応じてスケール可能
- リージョン/AZを選択してグローバル展開
- マネージドサービスで運用負荷を軽減

メリット:
- 初期投資不要（従量課金制）
- 迅速なサーバー起動（数分）
- 柔軟なスケーリング（自動スケーリング対応）
- 高可用性（複数AZ配置可能）
- グローバル展開が容易（世界中のリージョンで利用可能）
- 運用負荷の軽減（AWSがハードウェアを管理）
```

### 基本概念

#### EC2の役割

EC2は、仮想サーバー（インスタンス）を提供し、アプリケーションの実行環境を柔軟に構築できます。

```
EC2の役割
   ├─ 仮想サーバーの起動・停止
   ├─ 柔軟なスケーリング
   ├─ 従量課金制
   ├─ 豊富なインスタンス種類
   └─ カスタマイズ可能な環境
```

### インスタンス種類

#### 1. 汎用（General Purpose）

| インスタンス種類 | 用途 | CPU | メモリ | 価格（参考） |
|---|---|---|---|---|
| T3/T3a/T4g | Webサーバー、開発環境 | 2〜8 vCPU | 0.5〜32 GB | $0.0104/時間〜 |
| M6i/M6a/M7g | アプリケーションサーバー | 2〜128 vCPU | 8〜512 GB | $0.096/時間〜 |

**特徴:**
- T系: バースト可能、コスト効率に優れる
- M系: バランス型、汎用性が高い

#### 2. コンピューティング最適化（Compute Optimized）

| インスタンス種類 | 用途 | CPU | メモリ | 価格（参考） |
|---|---|---|---|---|
| C6i/C6a/C7g | HPC、バッチ処理、ゲームサーバー | 2〜128 vCPU | 4〜256 GB | $0.085/時間〜 |

**特徴:**
- 高性能CPU搭載
- コンピューティング集約型ワークロードに最適

#### 3. メモリ最適化（Memory Optimized）

| インスタンス種類 | 用途 | CPU | メモリ | 価格（参考） |
|---|---|---|---|---|
| R6i/R6a/R7g | データベース、キャッシュ、インメモリ処理 | 2〜128 vCPU | 16〜1024 GB | $0.126/時間〜 |
| X2iedn | SAP HANA、大規模DB | - | 最大4TB | - |

**特徴:**
- 大容量メモリ搭載
- メモリ集約型アプリケーションに最適

#### 4. ストレージ最適化（Storage Optimized）

| インスタンス種類 | 用途 | ストレージ特徴 |
|---|---|---|
| I4i | NoSQL DB、データウェアハウス | 高速NVMe SSD |
| D3 | 分散ファイルシステム | 大容量HDD |

#### 5. 高速コンピューティング（Accelerated Computing）

| インスタンス種類 | 用途 | GPU |
|---|---|---|
| P4/P5 | 機械学習、深層学習 | NVIDIA GPU 8〜16個 |
| G5 | グラフィックス、ゲームストリーミング | NVIDIA A10G |

### 購入オプション

| 購入オプション | 割引率 | コミットメント | 適用例 | 価格例 |
|---|---|---|---|---|
| **オンデマンド** | なし | なし | 短期ワークロード、予測不可能な負荷、開発・テスト | t3.medium: $0.0416/時間<br />m6i.large: $0.096/時間 |
| **リザーブド** | 最大72% | 1年/3年 | 長期安定ワークロード、予測可能な利用 | t3.medium: 最大54%割引<br />m6i.large: 最大72%割引 |
| **スポット** | 最大90% | なし | バッチ処理、データ分析、CI/CD、ステートレスアプリ | t3.medium: $0.0125/時間<br />m6i.large: $0.0288/時間 |
| **Savings Plans** | 最大72% | 1年/3年 | EC2/Lambda/Fargate横断利用 | Compute: 柔軟性高<br />EC2 Instance: 割引率高 |

**購入オプションの選び方:**
- **オンデマンド**: 時間単位課金、最小1分から、コミットメント不要
- **リザーブド**: 支払いオプション（全額前払い、一部前払い、前払いなし）選択可能
- **スポット**: AWS余剰キャパシティ利用、中断の可能性あり
- **Savings Plans**: インスタンス種類・リージョン変更可能

### ストレージ

#### 1. EBS（Elastic Block Store）料金

| ボリューム種類 | 用途 | IOPS | スループット | 価格 |
|---|---|---|---|---|
| **gp3**（推奨） | ほとんどのワークロード | 3,000〜16,000 | 125〜1,000 MB/s | **$0.08/GB/月** |
| **gp2**（旧世代） | 汎用 | 100〜16,000（サイズ連動） | - | $0.10/GB/月 |
| **io2** | データベース、高IOPS要求 | 最大64,000 | - | $0.125/GB/月 + IOPS料金 |
| **st1** | ビッグデータ、ログ処理 | - | 最大500 MB/s | $0.045/GB/月 |

#### 2. インスタンスストア

| 項目 | 内容 |
|---|---|
| **特徴** | 物理的に接続されたNVMe SSD、高速アクセス |
| **データ永続性** | 一時的（インスタンス停止で消失） |
| **料金** | 追加料金なし（インスタンス料金に含まれる） |
| **適用例** | キャッシュ、バッファ、スクラッチデータ |

### ネットワーク

#### ENI（Elastic Network Interface）

```yaml
特徴:
  - 仮想ネットワークカード
  - インスタンスにアタッチ
  - プライベートIP、パブリックIP
  - セキュリティグループ適用

用途:
  - 複数IPアドレス
  - 管理用ネットワーク分離
  - フェイルオーバー
```

#### 拡張ネットワーキング

```yaml
ENA（Elastic Network Adapter）:
  - 最大100 Gbps
  - 低レイテンシー
  - 高PPS（packets per second）
  - ほとんどのインスタンス種類でサポート

EFA（Elastic Fabric Adapter）:
  - HPC向け
  - OS-bypass
  - 超低レイテンシー
```

### セキュリティ

#### セキュリティグループ

```yaml
特徴:
  - ステートフルファイアウォール
  - インスタンスレベル
  - 許可ルールのみ

例:
  インバウンド:
    - SSH (22): 管理者IP
    - HTTP (80): 0.0.0.0/0
    - HTTPS (443): 0.0.0.0/0
  
  アウトバウンド:
    - デフォルト全許可
```

#### キーペア

```yaml
SSH接続:
  - 公開鍵・秘密鍵ペア
  - 起動時に指定
  - .pem形式

RDP接続:
  - Windowsインスタンス
  - キーペアで管理者パスワード復号化
```

### Auto Scaling

```yaml
Auto Scaling Group:
  最小: 2
  最大: 10
  希望: 3

スケーリングポリシー:
  ターゲット追跡:
    - CPU使用率70%維持
  
  ステップスケーリング:
    - CPU 80%以上: +2インスタンス
    - CPU 60%以下: -1インスタンス
  
  スケジュール:
    - 平日9-18時: 5インスタンス
    - それ以外: 2インスタンス
```

### まとめ

**EC2の重要ポイント:**

- **インスタンス種類選択**: ワークロードに応じた適切な選択
- **購入オプション**: コスト最適化（RI、Spot、Savings Plans）
- **ストレージ**: EBS種類選択、インスタンスストア理解
- **Auto Scaling**: 可用性とコスト最適化
- **セキュリティ**: セキュリティグループ、キーペア管理

EC2は、AWSの最も基本的で重要なコンピューティングサービスです。
