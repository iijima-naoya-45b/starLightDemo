## Amazon Redshift とは？

Amazon Redshiftは、フルマネージドなペタバイト規模のデータウェアハウスサービスです。大規模データの高速分析を低コストで実現します。

### 基本概念

```yaml
クラスター: Redshiftの基本単位
ノード: 計算・ストレージリソース
  - リーダーノード: クエリ調整、結果集約
  - コンピュートノード: クエリ実行、データ保存
スライス: ノード内の並列処理単位
データベース: データ格納単位
スキーマ: テーブルの論理グループ
```

### アーキテクチャ

```yaml
クライアント/アプリケーション
    ↓ (JDBC/ODBC)
リーダーノード
    ↓ (SQLパース、クエリプラン最適化)
コンピュートノード（複数）
    ↓ (並列処理)
S3（バックアップ、Spectrum）
```

### ノードタイプ

#### 1. RA3（Redshift Managed Storage）

```yaml
特徴:
  - ストレージとコンピュートの分離
  - S3ベースのマネージドストレージ
  - 自動階層化（ホット/コールドデータ）
  - スケーラビリティが高い

ノードサイズ:
  ra3.xlplus:
    - vCPU: 4
    - メモリ: 32GB
    - マネージドストレージ: 32TB
    - 推奨: 小〜中規模
    
  ra3.4xlarge:
    - vCPU: 12
    - メモリ: 96GB
    - マネージドストレージ: 128TB
    - 推奨: 中〜大規模
    
  ra3.16xlarge:
    - vCPU: 48
    - メモリ: 384GB
    - マネージドストレージ: 128TB
    - 推奨: 大規模、高パフォーマンス
```

#### 2. DC2（Dense Compute）

```yaml
特徴:
  - SSDベース
  - 高速な計算処理
  - ストレージ容量は限定的
  - レガシーノードタイプ

ノードサイズ:
  dc2.large:
    - vCPU: 2
    - メモリ: 15GB
    - SSD: 160GB
    
  dc2.8xlarge:
    - vCPU: 32
    - メモリ: 244GB
    - SSD: 2.56TB
```

### 主要機能

#### 1. 列指向ストレージ

```yaml
特徴:
  - カラム単位でデータ圧縮
  - 集計クエリの高速化
  - I/O削減
  
メリット:
  - 圧縮率: 最大10倍
  - クエリ速度: 最大10倍
  - ストレージコスト削減
```

#### 2. MPP（Massively Parallel Processing）

```yaml
特徴:
  - 複数ノードでクエリ並列実行
  - リーダーノードが調整
  - コンピュートノードが処理
  
スライス:
  - ノードあたり2-16スライス
  - 自動データ分散
```

#### 3. Redshift Spectrum

```yaml
特徴:
  - S3データを直接クエリ
  - クラスターにロード不要
  - Parquet、ORC、JSON対応
  
用途:
  - データレイク統合
  - 履歴データ分析
  - ETL処理削減
```

#### 4. Concurrency Scaling

```yaml
特徴:
  - 同時クエリ数増加時に自動スケール
  - 追加クラスター自動起動
  - 一貫したパフォーマンス
  
料金:
  - 1日1時間まで無料
  - 以降従量課金
```

#### 5. Materialized Views

```yaml
特徴:
  - 事前計算ビュー
  - クエリ高速化
  - 自動リフレッシュ
  
用途:
  - ダッシュボード
  - 定期レポート
```

#### 6. Automatic Workload Management (WLM)

```yaml
特徴:
  - クエリ優先度管理
  - リソース割り当て自動最適化
  - 短期・長期クエリの分離
```

### セキュリティ

```yaml
暗号化:
  保管時: AES-256（KMSまたはHSM）
  転送時: SSL/TLS
  
ネットワーク:
  - VPC配置
  - セキュリティグループ
  - プライベートサブネット推奨
  
認証:
  - IAM認証
  - データベースユーザー
  - SAML 2.0（SSO）
  
監査:
  - CloudTrail
  - データベース監査ログ
  - S3へのログ保存
```

### バックアップ

```yaml
自動スナップショット:
  - 8時間ごとまたは5GB変更ごと
  - 保持期間: 1-35日（デフォルト1日）
  - S3に保存
  
手動スナップショット:
  - 任意のタイミング
  - 削除まで保持
  
クロスリージョンスナップショット:
  - DR対策
  - 自動/手動コピー
```

### パフォーマンス最適化

```yaml
分散スタイル:
  KEY: 特定カラムでデータ分散
  ALL: 全ノードに全データコピー（小テーブル）
  EVEN: ラウンドロビン（デフォルト）
  AUTO: Redshiftが自動選択
  
ソートキー:
  - クエリフィルタ列
  - 範囲クエリ列
  - JOINキー
  
圧縮エンコーディング:
  - 自動圧縮（COPY時）
  - カラムごとに最適化
  - ANALYZE COMPRESSION
```

### まとめ

**Redshiftの重要ポイント:**
- ペタバイト規模のデータウェアハウス
- MPP並列処理で高速分析
- 列指向ストレージで圧縮率高い
- Spectrum でS3データ直接クエリ
- RA3ノード推奨（ストレージとコンピュート分離）
- PostgreSQL互換SQL
