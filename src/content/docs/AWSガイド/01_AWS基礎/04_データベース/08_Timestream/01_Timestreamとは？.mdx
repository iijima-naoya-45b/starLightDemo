## Amazon Timestream とは？

Amazon Timestreamは、フルマネージド型時系列データベースサービスです。IoTデバイス、産業機器、アプリケーションから生成される時系列データを高速かつコスト効率的に保存・分析できます。

### 時系列データとは？

```yaml
特徴:
  - 時間経過とともに記録されるデータ
  - タイムスタンプが必須
  - 追記型（Append-only）
  - 高頻度な書き込み

例:
  - IoT センサーデータ（温度、湿度、圧力）
  - DevOps メトリクス（CPU、メモリ、ネットワーク）
  - アプリケーションログ
  - 金融取引データ
  - クリックストリームデータ
```

### Timestreamの基本概念

```yaml
データベース:
  - 複数のテーブルを格納
  - アクセス制御単位

テーブル:
  - 時系列データ格納
  - スキーマレス
  - 保持ポリシー設定

レコード:
  - タイムスタンプ（必須）
  - ディメンション（タグ）
  - メジャー（測定値）

ディメンション:
  - データを分類する属性
  - 例: device_id, region, sensor_type

メジャー:
  - 時系列の測定値
  - 例: temperature, cpu_usage, pressure
```

### 2層ストレージアーキテクチャ

Timestreamは、データの新旧に応じて自動的に2つのストレージ層を使い分けます。

#### メモリストア（Memory Store）

```yaml
特徴:
  - 高速アクセス
  - 最近のデータ（デフォルト数時間〜数日）
  - インメモリ処理
  - ミリ秒単位のクエリ応答

用途:
  - リアルタイムダッシュボード
  - リアルタイムアラート
  - 直近データの高速分析

保持期間:
  - デフォルト: 24時間
  - 最大: 365日（推奨は数日）
  - 自動的にマグネティックストアへ移行
```

#### マグネティックストア（Magnetic Store）

```yaml
特徴:
  - コスト効率的
  - 長期保存（年単位）
  - S3ベース
  - 数秒単位のクエリ応答

用途:
  - 過去データの分析
  - トレンド分析
  - コンプライアンス
  - 機械学習

保持期間:
  - デフォルト: 無制限
  - 自動削除設定可能（日数指定）
  - 過去データも高速にクエリ可能
```

### データフロー

```yaml
1. データ書き込み:
   → メモリストア（最近のデータ）
   
2. 自動移行（保持ポリシーに基づく）:
   メモリストア → マグネティックストア
   
3. 自動削除（設定に基づく）:
   マグネティックストア → 削除

透過的なクエリ:
  - 両ストレージをシームレスにクエリ
  - ユーザーはストレージ層を意識不要
  - 自動的に最適化
```

### 主要機能

#### 1. 自動スケーリング

```yaml
特徴:
  - 書き込み・読み取り自動スケール
  - 容量管理不要
  - ダウンタイムなし
  - スパイクトラフィック対応

スループット:
  - 書き込み: 数百万レコード/秒
  - クエリ: 並列実行
```

#### 2. 適応型クエリエンジン

```yaml
特徴:
  - SQL互換クエリ言語
  - 時系列関数内蔵
  - 自動最適化
  - メモリ・マグネティック両ストア横断

時系列関数:
  - ago(): 相対時間指定
  - interpolate_linear(): 線形補間
  - fill(): 欠損値補完
  - binned averages: 時間窓集約
```

#### 3. データ保持ポリシー

```yaml
設定例:
  メモリストア保持期間: 24時間
  マグネティックストア保持期間: 365日
  
動作:
  - 24時間後: 自動的にマグネティックストアへ
  - 365日後: 自動削除
  - ダウンタイムなし
  - コスト最適化
```

#### 4. 統合機能

```yaml
AWS統合:
  - Kinesis Data Streams
  - Lambda
  - SageMaker（機械学習）
  - QuickSight（可視化）
  - Grafana
  
プロトコル:
  - JDBC
  - AWS SDK
  - HTTP API
```

### セキュリティ

```yaml
暗号化:
  保管時: KMS（デフォルト有効）
  転送時: TLS 1.2以上
  
アクセス制御:
  - IAMポリシー
  - きめ細かいアクセス制御
  - VPC Endpoints対応
  
監査:
  - CloudTrail統合
  - アクセスログ記録
```

```yaml
前提条件:
  - デバイス数: 1,000台
  - 測定間隔: 1分（1,440回/日/台）
  - レコードサイズ: 1KB
  - 日次書き込み: 1,440,000レコード（1,440回 × 1,000台）
  - 月次書き込み: 43,200,000レコード
  - メモリストア保持: 24時間
  - マグネティックストア保持: 365日
```

| 項目 | 計算 | 料金 |
|---|---|---|

**コスト最適化のポイント:**
- メモリストア保持期間を最小化（数時間〜1日）
- バッチ書き込みで書き込みコスト削減
- クエリの効率化（WHERE句でフィルタ）
- 不要データの早期削除
- マグネティックストアで長期保存コスト削減

### まとめ

**Timestreamの重要ポイント:**
- 時系列データ専用のマネージドDB
- 2層ストレージ（メモリ・マグネティック）で自動最適化
- 自動スケーリング、容量管理不要
- SQL互換クエリ、時系列関数内蔵
- IoT、DevOps、産業テレメトリに最適
- 従来のDBより10分の1のコストと1000倍のパフォーマンス
