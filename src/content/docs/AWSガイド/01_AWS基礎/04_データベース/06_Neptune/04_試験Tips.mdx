## Neptune 試験Tips (SAA/SAP)

### 頻出トピック

#### 1. Neptune vs 他のデータベース

```yaml
Neptune（グラフDB）:
  - 複雑な関係性
  - 多ホップクエリ
  - ソーシャルネットワーク
  - 推薦エンジン
  - 不正検知
  用途: 「関係性」「つながり」「ネットワーク」がキーワード

DynamoDB（NoSQL）:
  - キーバリュー
  - シンプルなクエリ
  - 高速読み書き
  - 無制限スケール
  用途: セッション、IoT、ゲーム

RDS（RDBMS）:
  - トランザクション
  - 複雑なSQL
  - JOIN、集計
  用途: 一般的な業務アプリケーション

DocumentDB（ドキュメントDB）:
  - MongoDB互換
  - JSONドキュメント
  - 柔軟なスキーマ
  用途: コンテンツ管理、カタログ
```

#### 2. Gremlin vs SPARQL

```yaml
Gremlin:
  - プロパティグラフ
  - トラバーサルベース
  - ソーシャルネットワーク分析
  - 推薦システム
  
SPARQL:
  - RDF（トリプル）
  - セマンティックWeb
  - ナレッジグラフ
  - オントロジー管理
  
試験のポイント:
  「関係性の探索」「推薦」→ Gremlin
  「ナレッジグラフ」「セマンティック」→ SPARQL
```

#### 3. 高可用性とスケーラビリティ

```yaml
Multi-AZ:
  - 3つのAZに自動レプリケーション
  - 30秒以内の自動フェイルオーバー
  - ストレージ自動修復
  
Read Replica:
  - 最大15個
  - 読み取りスケール
  - クロスリージョン可能
  
ストレージ:
  - 自動拡張（最大128TB）
  - 6ウェイレプリケーション
  - I/O自動最適化
```

### 典型的なシナリオ問題

#### シナリオ1: ソーシャルネットワーク

```yaml
問題:
  「SNSアプリで、ユーザーの友達、友達の友達を高速に検索したい。
   数百万のユーザーと数億の関係性を効率的に管理する必要がある。」

選択肢:
  A. RDS（MySQL）
  B. DynamoDB
  C. Neptune
  D. Redshift

正解: C. Neptune

理由:
  - 「友達の友達」= 多ホップクエリ
  - 「関係性」がキーワード
  - グラフデータベースが最適
  
RDSでは:
  - 複数回のJOINが必要
  - パフォーマンス低下
  
DynamoDBでは:
  - N+1問題
  - 複数回のクエリが必要
```

#### シナリオ2: 推薦エンジン

```yaml
問題:
  「ECサイトで『この商品を買った人は他にこんな商品も買っています』
   という推薦機能を実装したい。リアルタイムで計算する必要がある。」

選択肢:
  A. ElastiCache
  B. Neptune
  C. RDS
  D. DynamoDB + Lambda

正解: B. Neptune

理由:
  - 「買った人は他にも」= 協調フィルタリング
  - 複雑な関係性分析
  - リアルタイム計算
  
ポイント:
  - NeptuneのGremlinで効率的にトラバーサル
  - 2-3ホップ先の推薦が高速
```

#### シナリオ3: 不正検知

```yaml
問題:
  「金融システムで、複数アカウント間の循環取引を検出したい。
   リアルタイムでマネーロンダリングパターンを発見する必要がある。」

選択肢:
  A. RDS + stored procedure
  B. Neptune
  C. Athena
  D. EMR

正解: B. Neptune

理由:
  - 「循環取引」= グラフパターン
  - リアルタイム検出
  - 複雑な関係性分析
  
Neptune利点:
  - 循環パスの検出が効率的
  - リアルタイムクエリ
```

#### シナリオ4: ナレッジグラフ

```yaml
問題:
  「企業の技術文書、特許、論文を統合し、関連する情報を
   セマンティック検索で取得したい。」

選択肢:
  A. Neptune（Gremlin）
  B. Neptune（SPARQL）
  C. OpenSearch
  D. RDS

正解: B. Neptune（SPARQL）

理由:
  - 「ナレッジグラフ」がキーワード
  - 「セマンティック」→ RDF
  - オントロジー管理
  
ポイント:
  - SPARQL = W3C標準
  - RDFトリプル
```

### よくある間違い

```yaml
× 誤り: Neptuneで複雑なSQL実行
○ 正解: RDS使用（Neptuneはグラフクエリ専用）

× 誤り: 単純なキーバリュー検索にNeptune
○ 正解: DynamoDB（Neptuneはオーバースペック）

× 誤り: Neptuneはスケールしない
○ 正解: Read Replica（最大15個）で読み取りスケール

× 誤り: Neptuneでトランザクション処理
○ 正解: RDS（Neptuneはグラフトラバーサル専用）

× 誤り: プロパティグラフにSPARQL
○ 正解: Gremlin（SPARQLはRDF用）
```
