## Amazon Neptune とは？

Amazon Neptuneは、フルマネージド型グラフデータベースサービスです。高速で信頼性の高いグラフクエリを実行でき、複雑な関係性を持つデータの管理に最適化されています。

### グラフデータベースの基本概念

```yaml
ノード（Vertex）:
  - エンティティ（人、場所、物）
  - 例: ユーザー、商品、会社

エッジ（Edge）:
  - 関係性（つながり）
  - 例: フォロー、購入、所属

プロパティ:
  - ノードやエッジの属性
  - 例: 名前、年齢、日時
```

### 対応クエリ言語

#### 1. Gremlin（Apache TinkerPop）

```yaml
用途:
  - プロパティグラフモデル
  - トラバーサルベース
  - 複雑な関係性探索

特徴:
  - 命令型クエリ言語
  - ステップバイステップ処理
  - グラフトラバーサル最適化

主要操作:
  V(): 頂点取得
  E(): エッジ取得
  out(): 外向きトラバーサル
  in(): 内向きトラバーサル
  has(): フィルタ条件
```

**Gremlinクエリ例:**

```groovy
// ユーザーの友達を取得
g.V().hasLabel('User').has('name', 'Alice').out('friend').values('name')

// 2ホップ先の推薦
g.V().hasLabel('User').has('userId', 'u123')
  .out('purchased').in('purchased')
  .where(neq('u123'))
  .groupCount().by('userId')
  .order(local).by(values, desc)
```

#### 2. SPARQL（W3C標準）

```yaml
用途:
  - RDF（Resource Description Framework）
  - セマンティックWeb
  - ナレッジグラフ

特徴:
  - 宣言型クエリ言語
  - トリプル（Subject-Predicate-Object）
  - オントロジーサポート

主要操作:
  SELECT: データ取得
  CONSTRUCT: グラフ構築
  ASK: 存在確認
  DESCRIBE: リソース記述
```

**SPARQLクエリ例:**

```sparql
# ユーザーの友達を取得
PREFIX ex: <http://example.org/>
SELECT ?friendName
WHERE {
  ?user ex:name "Alice" .
  ?user ex:friend ?friend .
  ?friend ex:name ?friendName .
}

# カテゴリー別の商品数
SELECT ?category (COUNT(?product) as ?count)
WHERE {
  ?product ex:belongsTo ?category .
}
GROUP BY ?category
ORDER BY DESC(?count)
```

### Neptuneの主要機能

#### 1. 高可用性

```yaml
Multi-AZ:
  - 同期レプリケーション（3 AZ）
  - 自動フェイルオーバー（30秒以内）
  - ストレージ自動修復
  - 最大15個のRead Replica

ストレージ:
  - 自動10GB単位拡張
  - 最大128TB
  - 6ウェイレプリケーション
```

#### 2. バックアップとリカバリ

```yaml
自動バックアップ:
  - 継続バックアップ（35日間）
  - ポイントインタイムリカバリ
  - S3への自動保存

スナップショット:
  - 手動スナップショット
  - クロスリージョンコピー
  - スナップショットからの復元
```

#### 3. セキュリティ

```yaml
ネットワーク:
  - VPC内配置
  - セキュリティグループ
  - プライベートサブネット推奨

暗号化:
  - 保管時: KMS
  - 転送時: TLS 1.2

認証:
  - IAMデータベース認証
  - VPCエンドポイント
```

#### 4. パフォーマンス

```yaml
特徴:
  - ミリ秒単位レスポンス
  - 数十億の関係性処理
  - 並列クエリ実行
  - インデックス自動最適化

Neptune ML:
  - GraphSAGE
  - Deep Graph Library統合
  - SageMaker連携
```

### Gremlin vs SPARQL 選択ガイド

| 観点 | Gremlin | SPARQL |
|---|---|---|
| **データモデル** | プロパティグラフ | RDF（トリプル） |
| **クエリスタイル** | 命令型（トラバーサル） | 宣言型（パターンマッチング） |
| **主な用途** | ソーシャルネットワーク、推薦 | ナレッジグラフ、セマンティックWeb |
| **学習曲線** | 中程度 | やや高い |
| **標準化** | Apache TinkerPop | W3C標準 |

### まとめ

**Neptuneの重要ポイント:**
- フルマネージド型グラフデータベース
- GremlinとSPARQLの両方をサポート
- 高可用性（Multi-AZ、自動フェイルオーバー）
- ミリ秒単位の高速クエリ
- 数十億の関係性を効率的に処理
- Neptune MLで機械学習統合
