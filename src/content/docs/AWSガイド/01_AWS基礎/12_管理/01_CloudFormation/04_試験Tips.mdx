## CloudFormation 試験Tips (SAA/SAP)

### 頻出トピック

#### 1. CloudFormation vs Terraform

```yaml
CloudFormation:
  - AWS専用
  - 無料
  - AWS統合深い
  - JSON/YAML

Terraform:
  - マルチクラウド
  - HashiCorp製
  - HCL

頻出:
  Q: AWS IaC
  A: CloudFormation（または Terraform）
```

#### 2. 変更セット

```yaml
目的:
  - 更新プレビュー
  - 影響確認
  - リスク軽減

手順:
  1. 変更セット作成
  2. 変更内容確認
  3. 実行または破棄
```

#### 3. ドリフト検出

```yaml
概念:
  - テンプレートと実際の差異検出
  - 手動変更検知

用途:
  - コンプライアンス
  - 変更管理
```

### 頻出シナリオ

#### シナリオ1: 環境構築自動化

```
要件: 開発/本番環境を同じ構成で
解答: CloudFormationテンプレート + パラメータ

ポイント:
✓ パラメータで環境切替
✓ 一貫性保証
✓ 再現性
```

#### シナリオ2: マルチリージョン

```
要件: 複数リージョンに同じ構成
解答: CloudFormation StackSets

ポイント:
✓ マルチリージョン
✓ マルチアカウント
✓ 一括管理
```

### よくある間違い

```yaml
× 誤り: 手動変更後にCloudFormation更新
○ 正解: CloudFormationのみで管理

× 誤り: 全リソースを1スタック
○ 正解: 責務で分割（ネットワーク、アプリ等）

× 誤り: 変更セットなしで更新
○ 正解: 変更セットで影響確認
```
