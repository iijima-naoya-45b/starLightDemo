## Amazon SNS/SQS とは？

SNSとSQSは、メッセージングサービスです。非同期通信、疎結合アーキテクチャを実現します。

### SNS（Simple Notification Service）

```yaml
タイプ: Pub/Sub（1対多）
用途: 通知、ファンアウト

特徴:
  - トピックに複数サブスクライバー
  - プッシュ型
  - 即時配信

サブスクライバー:
  - Lambda
  - SQS
  - HTTP/HTTPS
  - Email
  - SMS
```

### SQS（Simple Queue Service）

```yaml
タイプ: メッセージキュー（1対1）
用途: 非同期処理、負荷平準化

キュータイプ:
  Standard:
    - 無制限スループット
    - At Least Once（重複可能性）
    - 順序保証なし
  
  FIFO:
    - 3,000メッセージ/秒（バッチ: 30,000）
    - Exactly Once（重複なし）
    - 順序保証あり
    - .fifo拡張子必須
```

### SQS主要機能

```yaml
可視性タイムアウト:
  - デフォルト: 30秒
  - 処理中は他の受信者から見えない
  - 処理完了後に削除

デッドレターキュー（DLQ）:
  - 処理失敗メッセージ保管
  - 最大受信回数設定

Long Polling:
  - 待機時間: 1-20秒
  - 空ポーリング削減
  - コスト削減

遅延キュー:
  - 配信遅延: 0-15分
  - 処理タイミング制御
```

### SNS + SQSパターン

```yaml
ファンアウト:
  SNS → SQS1（処理A）
      → SQS2（処理B）
      → Lambda（通知）

メリット:
  - 疎結合
  - 独立スケール
  - 再試行分離
```

### まとめ

**SNS/SQSの重要ポイント:**
- SNS: Pub/Sub、ファンアウト
- SQS: キュー、非同期処理
- FIFO: 順序保証、重複なし
- ファンアウトパターン: SNS + SQS
- DLQ: エラーハンドリング
