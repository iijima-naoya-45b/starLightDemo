## AWS Lambda とは？

AWS Lambdaは、サーバーレスコンピューティングサービスです。サーバー管理不要で、イベント駆動でコードを実行できます。
この資料は、**理想論ではなく、実務で使える実践的なLambdaの運用方法**を解説します。

### なぜLambdaが必要か

#### 問題のある構成（EC2/コンテナで常時起動サーバーを管理）

**問題のある状況:**

```
問題のある構成:
- サーバーの起動・停止管理が必要
- スケーリング設定が複雑
- アイドル時もコストが発生（常時課金）
- サーバーのメンテナンスが必要
- インフラの監視・管理が必要
- デプロイプロセスが複雑
- 低頻度処理でもサーバーを常時起動

影響:
- 無駄なコスト発生（アイドル時間の課金）
- 運用負荷が高い
- スケーリングの遅延
- インフラ管理に時間を取られる
- 小規模処理でも大きなサーバーが必要
```

**解決: Lambdaによるサーバーレスアーキテクチャ**

```
解決策:
- サーバー管理不要
- 自動スケーリング（同時実行数に応じて自動）
- 実行時間のみ課金（100msから課金）
- イベント駆動で自動実行
- 各種AWSサービスと統合

メリット:
- 運用負荷ゼロ（サーバー管理不要）
- コスト最適化（実行時間のみ課金、アイドル時ゼロ）
- 自動スケーリング（負荷に応じて自動）
- 迅速なデプロイ（コードのみ）
- 高可用性（AWSが管理）
- 開発者はコードに集中できる
```

### 基本概念

```yaml
特徴:
  - サーバー管理不要
  - 自動スケーリング
  - 従量課金（実行時間のみ）
  - イベント駆動
  - 100msから課金

制限:
  メモリ: 128MB 〜 10,240MB
  タイムアウト: 最大15分
  一時ストレージ: /tmp 最大10GB
  デプロイパッケージ: 50MB（zip）、250MB（解凍後）
  同時実行数: 1,000（デフォルト、上限緩和可能）
```

対応言語:

### 料金

| 料金項目 | 価格 | 無料枠 | 備考 |
|---|---|---|---|
| **リクエスト料金** | $0.20 / 100万リクエスト | 月100万リクエスト | リクエストごとに課金 |
| **実行時間料金** | $0.0000166667 / GB秒 | 月40万GB秒 | メモリ × 実行時間で計算 |

**料金計算例（128MB、100ms実行、100万リクエスト/月）:**

| 項目 | 計算 | 料金 |
|---|---|---|
| リクエスト料金 | 100万リクエスト × $0.20 | $0.20 |
| 実行時間料金 | (128MB/1024) × 0.1秒 × 100万 × $0.0000166667 | $0.21 |
| **合計** | - | **$0.41/月** |

**料金最適化のポイント:**
- メモリサイズの適切な設定（大きすぎると無駄、小さすぎると実行時間が長くなる）
- Provisioned Concurrency（常時起動）は別途料金発生
- クライアント側キャッシュでAPI呼び出し削減

### トリガー

```yaml
AWS統合:
  - API Gateway: REST API
  - ALB: HTTP(S)リクエスト
  - S3: オブジェクト作成/削除
  - DynamoDB Streams: テーブル変更
  - SNS/SQS: メッセージ
  - EventBridge: スケジュール、イベント
  - Kinesis: ストリーミング
  - CloudWatch Logs: ログフィルタ
```

### 実行環境

```yaml
コールドスタート:
  - 初回実行時の遅延
  - 数百ms 〜 数秒
  - 対策: Provisioned Concurrency

ウォームスタート:
  - 実行環境再利用
  - 数ms

/tmp:
  - 一時ストレージ
  - 最大10GB
  - 実行環境間で共有可能
```

### まとめ

**Lambdaの重要ポイント:**
- サーバーレス、自動スケーリング
- イベント駆動アーキテクチャ
- 従量課金でコスト効率
- 15分制限に注意
- コールドスタート対策
