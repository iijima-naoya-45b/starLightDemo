## Lambda 試験Tips (SAA/SAP)

### 頻出トピック

#### 1. Lambda制限

```yaml
必須暗記:
  メモリ: 128MB 〜 10,240MB
  タイムアウト: 最大15分
  /tmp: 最大10GB
  デプロイパッケージ: 50MB（zip）
  同時実行数: 1,000（デフォルト）

頻出問題:
  Q: 30分かかる処理をLambdaで
  A: ×不可能。Step Functions + Lambda分割
  
  Q: 大量の同時実行
  A: 予約済み同時実行数設定、または上限緩和
```

#### 2. コールドスタート対策

```yaml
問題: 初回実行遅延
解決策:
  - Provisioned Concurrency（有料）
  - コンテナイメージ最適化
  - VPC不使用（可能なら）
  - 言語選択（Python/Node.js推奨）
```

#### 3. Lambda vs EC2/ECS

```yaml
Lambda適用:
  - 短時間処理（15分以内）
  - イベント駆動
  - 予測不可能な負荷
  - 低頻度実行

EC2/ECS適用:
  - 長時間処理
  - 常時稼働
  - 予測可能な負荷
  - カスタムランタイム
```

### 頻出シナリオ

#### シナリオ1: 画像処理

```
要件: S3アップロード時に自動リサイズ
解答: S3イベント → Lambda → 処理 → S3保存

ポイント:
✓ イベント駆動
✓ スケーラブル
✓ コスト効率
```

#### シナリオ2: API バックエンド

```
要件: スパイク対応、低コスト
解答: API Gateway + Lambda + DynamoDB

ポイント:
✓ 自動スケール
✓ 従量課金
✓ サーバーレス
```

### よくある間違い

```yaml
× 誤り: 長時間バッチ処理をLambdaで
○ 正解: Step Functions + Lambda分割、またはBatch

× 誤り: 常時稼働にLambda
○ 正解: EC2/Fargate（コスト高くなる）

× 誤り: VPCに必ず配置
○ 正解: 不要なら配置しない（コールドスタート速い）
```
