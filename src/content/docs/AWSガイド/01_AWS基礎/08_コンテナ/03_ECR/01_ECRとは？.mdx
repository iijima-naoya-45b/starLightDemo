## Amazon ECR (Elastic Container Registry) とは？

ECRは、AWSが提供する完全マネージド型のDockerコンテナレジストリサービスです。コンテナイメージの保存、管理、デプロイを簡単に行えます。

### 基本概念

```yaml
リポジトリ:
  - コンテナイメージの保存場所
  - プライベート/パブリックリポジトリ
  - 各イメージはタグで識別

イメージ:
  - Dockerコンテナイメージ
  - OCI（Open Container Initiative）準拠
  - レイヤーベースのストレージ

タグ:
  - イメージのバージョン識別
  - latest、v1.0.0など
  - 複数タグ付与可能
```

### 主要機能

#### 1. リポジトリ管理

```yaml
プライベートリポジトリ:
  - デフォルト、セキュア
  - IAM認証制御
  - AWS内外からアクセス可能

パブリックリポジトリ:
  - インターネット公開
  - Docker Hubの代替
  - AWS アカウント不要でpull可能
  - ECR Public Gallery

リポジトリポリシー:
  - JSON形式
  - クロスアカウントアクセス
  - プル/プッシュ権限制御
```

#### 2. イメージスキャン

```yaml
脆弱性スキャン:
  - CVE（Common Vulnerabilities and Exposures）検出
  - プッシュ時自動スキャン
  - 手動スキャン実行可能

スキャンタイプ:
  基本スキャン:
    - AWS提供のスキャンエンジン
    - 無料
    - OSパッケージの脆弱性検出
  
  拡張スキャン:
    - Amazon Inspector統合
    - より詳細なスキャン
    - OS + アプリケーション依存関係
    - 継続的スキャン

結果:
  - 脆弱性の重要度（Critical、High、Medium、Low）
  - CVE ID
  - パッケージ名、バージョン
  - 修正バージョン情報
```

#### 3. ライフサイクルポリシー

```yaml
概要:
  - 古いイメージの自動削除
  - コスト最適化
  - ストレージ管理

ルール:
  - イメージ数上限
  - イメージ保持期間
  - タグステータス（tagged / untagged）
  - タグプレフィックスマッチング

例:
  - unttaggedイメージを30日後削除
  - 最新10イメージのみ保持
  - prodタグは無期限保持
```

#### 4. イメージレプリケーション

```yaml
クロスリージョンレプリケーション:
  - 複数リージョンに自動コピー
  - 低レイテンシアクセス
  - 災害対策

クロスアカウントレプリケーション:
  - 別AWSアカウントへコピー
  - マルチアカウント戦略
  - 組織間共有

設定:
  - レプリケーションルール
  - 送信元/送信先リージョン
  - フィルター（リポジトリプレフィックス）
```

### セキュリティ

#### 1. 認証・認可

```yaml
IAM:
  - ユーザー/ロールベース
  - きめ細かい権限制御
  - ecr:GetAuthorizationToken
  - ecr:BatchGetImage
  - ecr:PutImage

リポジトリポリシー:
  - リソースベース
  - クロスアカウント
  - プリンシパル指定
```

#### 2. データ保護

```yaml
暗号化:
  - 保存時暗号化（デフォルト）
  - AES-256
  - KMS統合可能（CMEK）

転送時暗号化:
  - HTTPS/TLS
  - Docker Registry API v2
```

#### 3. VPCエンドポイント

```yaml
PrivateLink:
  - インターネット経由不要
  - VPC内プライベート接続
  - セキュリティ向上

エンドポイント:
  - com.amazonaws.region.ecr.api
  - com.amazonaws.region.ecr.dkr
  - com.amazonaws.region.s3（レイヤー取得用）
```

### 統合サービス

```yaml
ECS/EKS:
  - タスク定義/Pod定義でイメージ指定
  - 自動認証
  - プル時のIAMロール使用

CodeBuild/CodePipeline:
  - CI/CDパイプライン統合
  - イメージビルド
  - 自動プッシュ

Lambda:
  - コンテナイメージサポート
  - 最大10GB
  - ECRから直接デプロイ

AWS App Runner:
  - ECRイメージから自動デプロイ
  - Web アプリケーション実行
```

### ベストプラクティス

```yaml
タグ戦略:
  - セマンティックバージョニング（v1.0.0）
  - Git コミットハッシュ
  - ビルド番号
  - 環境別タグ（prod、staging）

イメージ最適化:
  - マルチステージビルド
  - 軽量ベースイメージ（Alpine）
  - 不要ファイル削除
  - .dockerignore使用

セキュリティ:
  - 定期的な脆弱性スキャン
  - 最小権限の原則
  - イメージ署名（コンテンツトラスト）
  - 承認されたイメージのみ使用

コスト最適化:
  - ライフサイクルポリシー活用
  - 重複イメージ削除
  - 不要リポジトリ削除
```

### Docker Hub vs ECR

```yaml
ECR:
  メリット:
    - AWS統合深い
    - IAM認証
    - VPCエンドポイント
    - 低レイテンシ（AWS内）
    - 脆弱性スキャン標準
  
  デメリット:
    - AWSロックイン
    - 初期設定必要

Docker Hub:
  メリット:
    - 広く使用
    - パブリックイメージ豊富
    - 無料枠大きい
  
  デメリット:
    - Rate Limit（匿名: 100 pull/6時間）
    - AWS外ネットワーク
    - 追加コスト（データ転送）
```

### まとめ

**ECRの重要ポイント:**
- AWSネイティブなコンテナレジストリ
- IAM統合でセキュアなアクセス制御
- イメージスキャンで脆弱性検出
- ライフサイクルポリシーでコスト最適化
- ECS/EKS/Lambdaとシームレス統合
- クロスリージョン/アカウントレプリケーション対応
