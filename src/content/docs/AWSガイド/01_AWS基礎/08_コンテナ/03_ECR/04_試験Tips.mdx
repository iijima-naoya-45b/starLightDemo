## ECR 試験Tips (SAA/SAP)

### 頻出トピック

#### 1. ECR vs Docker Hub vs Harbor

```yaml
ECR（AWS推奨）:
  メリット:
    - AWS統合（IAM、VPC、ECS/EKS）
    - 低レイテンシ（AWS内）
    - セキュリティ（IAM、暗号化、VPCエンドポイント）
    - イメージスキャン標準
  
  デメリット:
    - AWSロックイン
  
  用途:
    - AWSでコンテナ実行
    - ECS/EKS/Lambda統合
    - エンタープライズセキュリティ

Docker Hub:
  メリット:
    - 広く利用
    - パブリックイメージ豊富
    - 無料枠
  
  デメリット:
    - Rate Limit（匿名: 100 pull/6時間、認証: 200 pull/6時間）
    - AWS外ネットワーク（データ転送料金）
    - 認証管理
  
  用途:
    - 開発環境
    - パブリックイメージ利用
    - マルチクラウド

Harbor（セルフホスト）:
  メリット:
    - オープンソース
    - オンプレミス
    - 完全制御
  
  デメリット:
    - インフラ管理必要
    - 運用コスト
  
  用途:
    - オンプレミス環境
    - 完全な制御必要

頻出:
  Q: AWSでECS実行、Docker Hubから頻繁にpull、Rate Limit問題
  A: ECRへイメージミラーリング/レプリケーション

  Q: コンテナイメージの脆弱性管理
  A: ECRイメージスキャン有効化
```

#### 2. ECR認証

```yaml
IAM認証:
  - GetAuthorizationToken（トークン取得）
  - BatchGetImage（イメージpull）
  - PutImage（イメージpush）
  - 12時間有効

クロスアカウント:
  - リポジトリポリシー（リソースベース）
  - IAMロール（アイデンティティベース）
  - 両方必要

VPCエンドポイント:
  - com.amazonaws.region.ecr.api（ECR API）
  - com.amazonaws.region.ecr.dkr（Docker Registry API）
  - com.amazonaws.region.s3（イメージレイヤー、Gateway型）
  - プライベートサブネットから接続

頻出:
  Q: プライベートサブネットのECS、インターネット不要でECR接続
  A: VPCエンドポイント（ecr.api、ecr.dkr、s3）

  Q: 別アカウントからECRアクセス
  A: リポジトリポリシー + IAMロール
```

#### 3. イメージスキャン

```yaml
基本スキャン:
  - 無料
  - OSパッケージの脆弱性
  - push時/手動

拡張スキャン:
  - Amazon Inspector統合
  - OSパッケージ + アプリケーション依存関係
  - 継続的スキャン
  - 料金: イメージ再スキャン毎

脆弱性重要度:
  - Critical（緊急）
  - High（高）
  - Medium（中）
  - Low（低）

頻出:
  Q: コンテナイメージの継続的セキュリティ評価
  A: ECR拡張スキャン（Enhanced Scanning）

  Q: イメージpush時自動スキャン
  A: scanOnPush=true
```

#### 4. ライフサイクルポリシー

```yaml
目的:
  - 古いイメージ自動削除
  - コスト最適化
  - ストレージ管理

ルールタイプ:
  tagStatus:
    - tagged（タグ付き）
    - untagged（タグなし）
    - any（すべて）
  
  countType:
    - imageCountMoreThan（イメージ数上限）
    - sinceImagePushed（経過日数）
  
  countUnit:
    - days（日）

優先度:
  - rulePriority（数値小が優先）

頻出:
  Q: タグのないイメージが増加、コスト削減
  A: ライフサイクルポリシー（untagged、7日後削除）

  Q: 本番イメージは保持、開発イメージは自動削除
  A: tagPrefixList使用（prod保持、dev削除）
```

#### 5. レプリケーション

```yaml
クロスリージョン:
  - 複数リージョンに自動コピー
  - 低レイテンシ
  - 災害対策

クロスアカウント:
  - 別アカウントへコピー
  - マルチアカウント戦略

設定:
  - レプリケーションルール
  - リポジトリフィルター（PREFIX_MATCH）
  - 自動・非同期

頻出:
  Q: グローバル展開、各リージョンで低レイテンシpull
  A: クロスリージョンレプリケーション

  Q: 開発アカウントでビルド、本番アカウントでデプロイ
  A: クロスアカウントレプリケーション
```

### 頻出シナリオ

#### シナリオ1: Docker Hub Rate Limit回避

```
要件:
  - ECSでコンテナ実行
  - Docker Hubから頻繁にpull
  - Rate Limit問題

解答:
  ✓ ECRへイメージコピー
  ✓ ECSタスク定義でECRイメージ参照
  ✓ VPCエンドポイント使用（プライベート接続）

ポイント:
  - Docker Hub Rate Limit: 匿名100 pull/6時間
  - ECR: Rate Limitなし
  - 同一リージョン内データ転送無料
```

#### シナリオ2: セキュアなコンテナ管理

```
要件:
  - コンテナイメージの脆弱性管理
  - 重大な脆弱性検出時デプロイブロック
  - 監査証跡

解答:
  ✓ ECRイメージスキャン有効化（scanOnPush=true）
  ✓ EventBridge + Lambda（脆弱性検出時通知）
  ✓ イミュータブルタグ（IMMUTABLE）
  ✓ CloudTrail監査

ポイント:
  - 自動スキャン
  - EventBridgeでワークフロー統合
  - イミュータブルタグで改ざん防止
```

#### シナリオ3: マルチリージョン展開

```
要件:
  - グローバルサービス
  - 各リージョンで低レイテンシ
  - 災害対策

解答:
  ✓ クロスリージョンレプリケーション
  ✓ 各リージョンのECS/EKSでローカルECR使用
  ✓ Route 53でグローバルロードバランシング

ポイント:
  - 自動レプリケーション
  - リージョン障害時の可用性
  - データ転送料金（クロスリージョン: $0.02/GB）
```

#### シナリオ4: プライベートサブネットからのECRアクセス

```
要件:
  - プライベートサブネットのECS
  - インターネットゲートウェイなし
  - ECRからイメージpull

解答:
  ✓ VPCエンドポイント作成:
    - com.amazonaws.region.ecr.api
    - com.amazonaws.region.ecr.dkr
    - com.amazonaws.region.s3（Gateway型）
  ✓ セキュリティグループ設定（HTTPS: 443）

ポイント:
  - 3つのエンドポイント必要
  - S3はGateway型（無料）
  - NAT Gateway不要
```

#### シナリオ5: コスト最適化

```
要件:
  - ECRストレージコスト削減
  - 古いイメージが蓄積
  - 本番イメージは保持

解答:
  ✓ ライフサイクルポリシー:
    - untaggedイメージ: 7日後削除
    - taggedイメージ: 最新10個のみ保持
    - prodタグ: 削除しない

ポイント:
  - 自動削除
  - タグ別ルール
  - rulePriority で優先度制御
```

### よくある間違い

```yaml
× 誤り: Docker Hubで本番運用（AWS内）
○ 正解: ECR使用（AWS統合、Rate Limitなし）

× 誤り: パブリックサブネットからECR、IGW経由
○ 正解: VPCエンドポイント（プライベート接続、セキュア）

× 誤り: ECRトークン一度取得で永久使用
○ 正解: 12時間毎に再取得（get-login-password）

× 誤り: イメージスキャンは手動のみ
○ 正解: scanOnPush=true で自動化

× 誤り: ライフサイクルポリシーで即時削除
○ 正解: 条件（日数、数）に基づき自動削除

× 誤り: クロスアカウントはリポジトリポリシーのみ
○ 正解: リポジトリポリシー + IAMロール両方

× 誤り: レプリケーションは手動コピー
○ 正解: 自動レプリケーション（設定のみ）
```

### 試験での選択基準

```yaml
Docker Hub選択:
  - 開発環境
  - パブリックイメージ使用
  - マルチクラウド必要
  - コスト最優先（小規模）

ECR選択:
  - 本番環境
  - AWS統合（ECS/EKS/Lambda）
  - セキュリティ重視
  - Rate Limit問題
  - VPCエンドポイント必要
  - 脆弱性スキャン必要
  - クロスリージョン/アカウント必要

Harbor選択:
  - オンプレミス
  - 完全制御必要
  - データ主権/コンプライアンス
```

### 覚えるべき数値

```yaml
料金:
  - ストレージ: $0.10 / GB / 月
  - データ転送（同一リージョン）: 無料
  - データ転送（クロスリージョン）: $0.02 / GB

制限:
  - トークン有効期限: 12時間
  - イメージサイズ上限（Lambda）: 10GB
  - リポジトリ数: デフォルト10,000（上限緩和可能）

Docker Hub Rate Limit:
  - 匿名: 100 pull / 6時間
  - 認証済み（無料）: 200 pull / 6時間
  - Pro: 5,000 pull / 日
```

### まとめ

**ECR試験対策の重要ポイント:**
- ECR vs Docker Hub vs Harbor の使い分け
- VPCエンドポイント3つ（ecr.api、ecr.dkr、s3）
- イメージスキャン（基本/拡張）で脆弱性管理
- ライフサイクルポリシーでコスト最適化
- クロスリージョン/アカウントレプリケーション
- 12時間トークン有効期限
- Docker Hub Rate Limit問題 → ECR移行
