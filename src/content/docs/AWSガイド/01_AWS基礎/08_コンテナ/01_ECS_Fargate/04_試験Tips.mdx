## ECS/Fargate 試験Tips (SAA/SAP)

### 頻出トピック

#### 1. EC2 vs Fargate

```yaml
Fargate（推奨）:
  - サーバーレス
  - インフラ管理不要
  - タスク単位課金
  - 簡単、迅速
  - 用途: ほとんどのケース

EC2起動種類:
  - インスタンス管理必要
  - 柔軟な設定
  - コスト効率（大規模）
  - 用途: 大規模、特殊要件

頻出:
  Q: コンテナ実行、管理簡素化
  A: Fargate

  Q: 大規模、コスト最適化
  A: EC2起動種類
```

#### 2. タスク vs サービス

```yaml
タスク:
  - 1回限り実行
  - バッチ処理
  - run-task

サービス:
  - 長期実行
  - Auto Scaling
  - ALB統合
  - create-service
```

#### 3. ネットワークモード

```yaml
awsvpc（Fargate必須）:
  - タスク専用ENI
  - セキュリティグループ
  - 推奨

bridge/host:
  - EC2起動種類のみ
  - レガシー
```

### 頻出シナリオ

#### シナリオ1: マイクロサービス

```
要件: コンテナベースマイクロサービス、管理簡素化
解答: Fargate + ALB + ECS Service

ポイント:
✓ サーバー管理不要
✓ Auto Scaling
✓ ALB統合
```

#### シナリオ2: バッチ処理

```
要件: 日次バッチ、コンテナ実行
解答: EventBridge + ECS Task（Fargate）

ポイント:
✓ スケジュール実行
✓ 完了後自動削除
✓ コスト効率
```

#### シナリオ3: 大規模コンテナ

```
要件: 数百コンテナ、コスト最適化
解答: EC2起動種類 + Fargate Spot

ポイント:
✓ EC2でベースライン
✓ Spotでコスト削減
```

### よくある間違い

```yaml
× 誤り: Fargateでホストネットワーク
○ 正解: Fargateはawsvpc必須

× 誤り: サービスで1回限り実行
○ 正解: タスク（run-task）使用

× 誤り: Fargateで常にコスト高
○ 正解: 管理コスト含めると中小規模で効率的
```
