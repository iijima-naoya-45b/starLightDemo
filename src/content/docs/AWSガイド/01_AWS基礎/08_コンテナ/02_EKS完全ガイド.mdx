## Amazon EKS 完全ガイド

Amazon Elastic Kubernetes Service (EKS) は、AWSでKubernetesクラスターを簡単に実行できるマネージドサービスです。Kubernetesのコントロールプレーンを自動管理します。

### EKSの特徴

#### 1. 主要な特徴

**マネージドKubernetes:**

- **コントロールプレーン管理**: 自動アップグレード、パッチ適用
- **高可用性**: マルチAZ構成
- **統合**: IAM、VPC、ELB、EBS等と統合
- **セキュリティ**: AWS Secrets Manager、KMS統合

**スケーラビリティ:**

- **Cluster Autoscaler**: ノード自動スケーリング
- **Horizontal Pod Autoscaler (HPA)**: Pod自動スケーリング
- **Vertical Pod Autoscaler (VPA)**: リソース自動調整
- **Karpenter**: 高速なノードプロビジョニング

**コンピュートオプション:**

- **EC2**: 完全な制御、カスタマイズ可能
- **Fargate**: サーバーレス、運用不要
- **Managed Node Groups**: ノードライフサイクル管理

### EKSクラスター構築

#### 1. eksctlによる構築

```bash
# eksctlのインストール
curl --silent --location "https://github.com/weaveworks/eksctl/releases/latest/download/eksctl_$(uname -s)_amd64.tar.gz" | tar xz -C /tmp
sudo mv /tmp/eksctl /usr/local/bin

# クラスター作成（基本）
eksctl create cluster \
  --name production-cluster \
  --region ap-northeast-1 \
  --version 1.28 \
  --nodegroup-name standard-workers \
  --node-type t3.medium \
  --nodes 3 \
  --nodes-min 1 \
  --nodes-max 5 \
  --managed

# クラスター作成（詳細設定）
eksctl create cluster \
  --name production-cluster \
  --region ap-northeast-1 \
  --version 1.28 \
  --vpc-cidr 10.0.0.0/16 \
  --with-oidc \
  --ssh-access \
  --ssh-public-key my-key \
  --managed \
  --node-type t3.large \
  --nodes 3 \
  --nodes-min 2 \
  --nodes-max 10 \
  --node-volume-size 50 \
  --node-labels "environment=production,team=platform" \
  --tags "Environment=Production,ManagedBy=eksctl"

# kubeconfigの設定
aws eks update-kubeconfig --region ap-northeast-1 --name production-cluster

# クラスター確認
kubectl cluster-info
kubectl get nodes
```

#### 2. CloudFormation/Terraformによる構築

```yaml
# eksctl設定ファイル (cluster.yaml)
apiVersion: eksctl.io/v1alpha5
kind: ClusterConfig

metadata:
  name: production-cluster
  region: ap-northeast-1
  version: "1.28"
  tags:
    Environment: Production
    ManagedBy: eksctl

vpc:
  cidr: 10.0.0.0/16
  nat:
    gateway: HighlyAvailable  # マルチAZ NAT Gateway

iam:
  withOIDC: true
  serviceAccounts:
    - metadata:
        name: aws-load-balancer-controller
        namespace: kube-system
      wellKnownPolicies:
        awsLoadBalancerController: true
    - metadata:
        name: cluster-autoscaler
        namespace: kube-system
      wellKnownPolicies:
        autoScaler: true

managedNodeGroups:
  - name: ng-general
    instanceType: t3.medium
    minSize: 2
    maxSize: 10
    desiredCapacity: 3
    volumeSize: 50
    ssh:
      publicKeyName: my-key
    labels:
      role: general
    tags:
      NodeType: general
    iam:
      withAddonPolicies:
        imageBuilder: true
        autoScaler: true
        externalDNS: true
        certManager: true
        appMesh: true
        ebs: true
        efs: true
        albIngress: true
        cloudWatch: true

  - name: ng-spot
    instanceTypes:
      - t3.medium
      - t3.large
    spot: true
    minSize: 0
    maxSize: 5
    desiredCapacity: 2
    labels:
      lifecycle: spot
    taints:
      - key: spot
        value: "true"
        effect: NoSchedule

addons:
  - name: vpc-cni
    version: latest
  - name: coredns
    version: latest
  - name: kube-proxy
    version: latest

cloudWatch:
  clusterLogging:
    enableTypes:
      - api
      - audit
      - authenticator
      - controllerManager
      - scheduler
```

```bash
# 設定ファイルからクラスター作成
eksctl create cluster -f cluster.yaml

# ノードグループ追加
eksctl create nodegroup --config-file=cluster.yaml --include=ng-spot
```

#### 2. Ingress（ALB）

```yaml
# ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: web-app-ingress
  namespace: production
  annotations:
    # AWS Load Balancer Controller
    kubernetes.io/ingress.class: alb
    alb.ingress.kubernetes.io/scheme: internet-facing
    alb.ingress.kubernetes.io/target-type: ip
    
    # SSL設定
    alb.ingress.kubernetes.io/certificate-arn: arn:aws:acm:ap-northeast-1:123456789012:certificate/xxx
    alb.ingress.kubernetes.io/ssl-policy: ELBSecurityPolicy-TLS-1-2-2017-01
    alb.ingress.kubernetes.io/listen-ports: '[{"HTTP": 80}, {"HTTPS": 443}]'
    alb.ingress.kubernetes.io/ssl-redirect: '443'
    
    # ヘルスチェック
    alb.ingress.kubernetes.io/healthcheck-path: /health
    alb.ingress.kubernetes.io/healthcheck-interval-seconds: '30'
    alb.ingress.kubernetes.io/healthcheck-timeout-seconds: '5'
    alb.ingress.kubernetes.io/healthy-threshold-count: '2'
    alb.ingress.kubernetes.io/unhealthy-threshold-count: '2'
    
    # セキュリティ
    alb.ingress.kubernetes.io/security-groups: sg-xxxxx
    alb.ingress.kubernetes.io/subnets: subnet-xxxxx,subnet-yyyyy,subnet-zzzzz
    
    # タグ
    alb.ingress.kubernetes.io/tags: Environment=Production,Application=WebApp
spec:
  rules:
    - host: app.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: web-app-service
                port:
                  number: 80
          - path: /api
            pathType: Prefix
            backend:
              service:
                name: api-service
                port:
                  number: 80
```

#### 3. HPA（Horizontal Pod Autoscaler）

```yaml
# hpa.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: web-app-hpa
  namespace: production
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: web-app
  minReplicas: 3
  maxReplicas: 20
  metrics:
    - type: Resource
      resource:
        name: cpu
        target:
          type: Utilization
          averageUtilization: 70
    - type: Resource
      resource:
        name: memory
        target:
          type: Utilization
          averageUtilization: 80
  behavior:
    scaleDown:
      stabilizationWindowSeconds: 300
      policies:
        - type: Percent
          value: 50
          periodSeconds: 60
    scaleUp:
      stabilizationWindowSeconds: 0
      policies:
        - type: Percent
          value: 100
          periodSeconds: 30
        - type: Pods
          value: 4
          periodSeconds: 60
      selectPolicy: Max
```

```yaml

  name: web-app-sa
  namespace: production

    eks.amazonaws.com/role-arn: arn:aws:iam::123456789012:role/WebAppRole
```

```bash
# IAMロール作成
eksctl create iamserviceaccount \
  --name web-app-sa \
  --namespace production \
  --cluster production-cluster \
  --attach-policy-arn arn:aws:iam::aws:policy/AmazonS3ReadOnlyAccess \
  --attach-policy-arn arn:aws:iam::aws:policy/AmazonDynamoDBReadOnlyAccess \
  --approve \
  --override-existing-serviceaccounts
```

### CI/CD統合

```yaml
# .github/workflows/deploy.yml
name: Deploy to EKS

on:
  push:
    branches:
      - main

env:
  AWS_REGION: ap-northeast-1
  EKS_CLUSTER_NAME: production-cluster
  ECR_REPOSITORY: web-app
  NAMESPACE: production

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout
        uses: actions/checkout@v3
      
      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v2
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: ${{ env.AWS_REGION }}
      
      - name: Login to Amazon ECR
        id: login-ecr
        uses: aws-actions/amazon-ecr-login@v1
      
      - name: Build and push image
        env:
          ECR_REGISTRY: ${{ steps.login-ecr.outputs.registry }}
          IMAGE_TAG: ${{ github.sha }}
        run: |
          docker build -t $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG .
          docker push $ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG
      
      - name: Update kubeconfig
        run: |
          aws eks update-kubeconfig --name $EKS_CLUSTER_NAME --region $AWS_REGION
      
      - name: Deploy to EKS
        env:
          ECR_REGISTRY: ${{ steps.login-ecr.outputs.registry }}
          IMAGE_TAG: ${{ github.sha }}
        run: |
          kubectl set image deployment/web-app \
            app=$ECR_REGISTRY/$ECR_REPOSITORY:$IMAGE_TAG \
            -n $NAMESPACE
          kubectl rollout status deployment/web-app -n $NAMESPACE
```

### まとめ

**EKSの主要な利点:**

- **マネージド**: コントロールプレーン管理不要
- **高可用性**: マルチAZ構成
- **セキュリティ**: IAM、VPC統合
- **スケーラビリティ**: 自動スケーリング
- **統合**: AWSサービスとの統合

**SAA/SAP試験での重要ポイント:**

1. **コンピュートオプション**: EC2 vs Fargate
2. **ネットワーク**: VPC、サブネット設計
3. **ストレージ**: EBS vs EFS
4. **セキュリティ**: IRSA、Network Policy
5. **スケーリング**: HPA、Cluster Autoscaler、Karpenter

EKSは、Kubernetesをマネージドで実行できる強力なサービスです。適切な設計により、高可用性でスケーラブルなコンテナ環境を構築できます。
