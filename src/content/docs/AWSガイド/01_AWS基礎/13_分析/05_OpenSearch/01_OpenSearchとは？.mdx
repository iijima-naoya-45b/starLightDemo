## Amazon OpenSearch Service とは？

OpenSearch Serviceは、ログ分析、フルテキスト検索、セキュリティ分析などに対応したマネージドの検索・分析エンジンです。

### 主要機能

#### 1. 検索・分析エンジン

```yaml
概要:
  - Elasticsearch互換
  - フルテキスト検索
  - リアルタイム分析
  - ログ分析
  - セキュリティ分析（SIEM）

特徴:
  - マネージドサービス
  - 自動バックアップ
  - 自動パッチ適用
  - Multi-AZ対応
  - スケーラブル
```

#### 2. Elasticsearch互換性

```yaml
互換性:
  OpenSearch:
    - Elasticsearch 7.10.2ベース
    - オープンソース
    - Apache 2.0ライセンス
  
  Elasticsearch OSS:
    - 7.10.2まで完全互換
    - 既存アプリケーション移行容易
  
  API互換:
    - REST API
    - クエリDSL
    - Bulk API
    - 検索API

サポートバージョン:
  - OpenSearch 1.x / 2.x
  - Elasticsearch 7.x（レガシー）
```

#### 3. Kibana（OpenSearch Dashboards）

```yaml
機能:
  可視化:
    - ダッシュボード作成
    - グラフ・チャート
    - 地図表示
  
  分析:
    - ログ検索
    - クエリ実行
    - フィルタリング
  
  管理:
    - インデックス管理
    - セキュリティ設定
    - アラート設定

アクセス:
  - Webブラウザ経由
  - Cognito統合
  - SAML認証対応
```

### アーキテクチャ

```yaml
構成要素:
  ドメイン:
    - クラスター単位
    - 独立したOpenSearch環境
  
  ノード:
    データノード:
      - データ保存・検索
      - インデックス処理
    
    マスターノード:
      - クラスター管理
      - メタデータ管理
      - 推奨: 3台（奇数）
    
    UltraWarmノード:
      - 読み取り専用データ
      - S3ベース
      - コスト削減
    
    コールドストレージ:
      - アーカイブデータ
      - S3保存
      - 最低コスト
  
  ストレージ:
    - EBSボリューム
    - インスタンスストア
    - UltraWarm（S3）
```

### データ構造

```yaml
基本概念:
  インデックス:
    - データの論理的なコンテナ
    - RDBのデータベース相当
  
  ドキュメント:
    - JSONフォーマット
    - RDBのレコード相当
    - 一意のID
  
  フィールド:
    - ドキュメントの属性
    - RDBのカラム相当
    - データ型定義

例:
  インデックス: application-logs-2024-01
  ドキュメント:
    {
      "timestamp": "2024-01-15T10:30:00Z",
      "level": "ERROR",
      "message": "Connection timeout",
      "service": "api-gateway"
    }
```

### インデックス管理

```yaml
Index State Management (ISM):
  概念:
    - インデックスライフサイクル管理
    - 自動化ポリシー
  
  ステート:
    Hot:
      - 最新データ
      - 書き込み・検索頻繁
      - 高性能ストレージ
    
    Warm:
      - 過去データ
      - 検索のみ
      - UltraWarm移行
    
    Cold:
      - アーカイブ
      - 低頻度アクセス
      - S3保存
    
    Delete:
      - 自動削除
      - 保持期間経過後

ポリシー例:
  - 7日後にWarmへ移行
  - 30日後にColdへ移行
  - 90日後に削除
```

### スケーリング

```yaml
垂直スケーリング:
  - インスタンスタイプ変更
  - ストレージ拡張
  - ダウンタイム最小化

水平スケーリング:
  ノード追加:
    - データノード増減
    - 自動シャード再配置
  
  シャード:
    - データの分散単位
    - プライマリ + レプリカ
    - 適切な数の設定重要

Auto-Tune:
  - 自動パフォーマンス最適化
  - メモリ・JVM設定調整
  - 推奨設定適用
```

### セキュリティ

```yaml
暗号化:
  保管時:
    - EBSボリューム暗号化
    - KMS統合
    - UltraWarm暗号化
  
  転送中:
    - TLS/SSL（ノード間）
    - HTTPS（クライアント）

認証:
  - IAM統合
  - Cognito
  - SAML 2.0
  - 基本認証

認可:
  Fine-grained Access Control:
    - ユーザー/ロール管理
    - インデックスレベル制御
    - ドキュメントレベル制御
    - フィールドレベルマスキング

ネットワーク:
  - VPC内配置
  - VPCエンドポイント
  - セキュリティグループ
  - パブリック/プライベートアクセス
```

### 可用性・耐障害性

```yaml
Multi-AZ:
  - 3つのAZ推奨
  - 自動フェイルオーバー
  - レプリカ配置

スナップショット:
  自動:
    - 毎日実行
    - 14日間保持
    - 手動設定変更可能
  
  手動:
    - オンデマンド取得
    - S3保存
    - リージョン間コピー可能

リストア:
  - 新しいドメイン作成
  - インデックス単位復元
  - クロスリージョン復元
```

### データ取り込み

```yaml
方法:
  REST API:
    - 直接インデックス
    - Bulk API（大量データ）
  
  AWS統合:
    Kinesis Firehose:
      - ストリーミング取り込み
      - 自動バッファリング
      - 変換可能
    
    Lambda:
      - イベント駆動
      - データ変換
      - S3/DynamoDB連携
    
    CloudWatch Logs:
      - ログサブスクリプション
      - リアルタイム転送
    
    Logstash:
      - データパイプライン
      - フィルタリング・変換
      - 複数ソース統合
  
  Beats:
    - Filebeat（ログファイル）
    - Metricbeat（メトリクス）
    - 軽量エージェント
```

### クエリと検索

```yaml
クエリ方法:
  Query DSL:
    - JSON形式
    - 強力な検索構文
    - 全文検索
    - フィルタリング
  
  SQL:
    - SQLクエリ対応
    - JDBC/ODBC接続
    - BIツール統合

検索機能:
  - フルテキスト検索
  - ファジー検索
  - 集計（Aggregations）
  - 地理空間検索
  - スクリプトフィールド
```

### 統合サービス

```yaml
ログ収集:
  - CloudWatch Logs
  - Kinesis Data Firehose
  - AWS Lambda
  - Logstash

可視化:
  - OpenSearch Dashboards
  - Kibana（レガシー）
  - Grafana

監視:
  - CloudWatch

  - X-Ray

セキュリティ:
  - Security Hub

```

### OpenSearch Serverless

```yaml
概念:
  - サーバーレス実行
  - インフラ管理不要
  - 自動スケーリング
  - OCU（OpenSearch Compute Units）課金

用途:
  - 不定期ワークロード
  - 開発・テスト
  - マイクロサービス

料金:
  - OCU時間課金
  - インデックスOCU: $0.334/時間
  - 検索OCU: $0.334/時間
```

### まとめ

**OpenSearchの重要ポイント:**
- Elasticsearch互換の検索・分析エンジン
- ログ分析、フルテキスト検索、SIEM
- OpenSearch Dashboards（Kibana）で可視化
- Multi-AZ、自動バックアップで高可用性
- UltraWarm・Coldストレージでコスト削減
- Kinesis Firehose、Lambda統合
- インデックスライフサイクル管理
- Fine-grained Access Controlでセキュリティ
