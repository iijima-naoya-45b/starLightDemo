## Amazon EMR とは？

EMR（Elastic MapReduce）は、ビッグデータフレームワークを実行するためのマネージドクラスタープラットフォームです。

### 主要機能

#### 1. サポートフレームワーク

```yaml
Apache Spark:
  - 高速分散処理
  - インメモリ処理
  - バッチ・ストリーミング
  - 機械学習（MLlib）

Apache Hadoop:
  - MapReduce
  - HDFS
  - YARN
  - 大規模バッチ処理

Presto:
  - インタラクティブSQL
  - 複数データソース統合
  - 低レイテンシクエリ

Hive:
  - SQL on Hadoop
  - データウェアハウス
  - バッチクエリ

その他:
  - HBase（NoSQLデータベース）
  - Flink（ストリーム処理）
  - Hudi（データレイク）
  - Trino（分散SQLクエリ）
  - TensorFlow（機械学習）
  - Apache Zeppelin（ノートブック）
```

#### 2. クラスター構成

```yaml
ノードタイプ:
  Master Node（プライマリノード）:
    - クラスター管理
    - タスク調整
    - YARN ResourceManager
    - HDFS NameNode
    - 必須: 1台（HA構成で3台）
  
  Core Node:
    - タスク実行
    - データ保存（HDFS）
    - YARN NodeManager
    - HDFS DataNode
    - 最小: 1台〜
  
  Task Node（オプション）:
    - タスク実行のみ
    - データ保存なし
    - Spot Instance推奨
    - スケーラブル

ストレージ:
  HDFS:
    - クラスター内分散ストレージ
    - Core Node上
    - 高速アクセス
  
  EMRFS:
    - S3直接アクセス
    - クラスター外永続化
    - コスト効率
    - 推奨ストレージ
```

#### 3. デプロイメントモード

```yaml
クラスターモード:
  長時間実行:
    - 常時起動
    - インタラクティブ分析
    - 複数ジョブ実行
    - コスト: 高
  
  一時的クラスター:
    - ジョブ単位起動
    - ジョブ完了後終了
    - 自動化推奨
    - コスト: 最適化

EMR on EC2:
  - EC2インスタンス使用
  - 完全制御
  - カスタマイズ自由
  - 最も一般的

EMR on EKS:
  - Kubernetes上で実行
  - コンテナベース
  - マルチテナント
  - EKS既存環境活用

EMR Serverless:
  - サーバーレス実行
  - インフラ管理不要
  - 自動スケーリング
  - ジョブ単位課金

EMR on Outposts:
  - オンプレミス実行
  - ハイブリッド環境
  - レイテンシ要件
```

### Apache Spark

```yaml
概要:
  - 高速分散処理エンジン
  - インメモリ処理
  - Hadoopより最大100倍高速

主要コンポーネント:
  Spark Core:
    - RDD（Resilient Distributed Dataset）
    - 基本的な分散処理

  Spark SQL:
    - DataFrameベース
    - SQL処理
    - 構造化データ

  Spark Streaming:
    - リアルタイムストリーム処理
    - マイクロバッチ
    - Kinesis統合

  MLlib:
    - 機械学習ライブラリ
    - 分類、回帰、クラスタリング
    - 分散学習

  GraphX:
    - グラフ処理
    - ソーシャルネットワーク分析

言語サポート:
  - Scala（ネイティブ）
  - Python（PySpark）
  - Java
  - R（SparkR）
  - SQL
```

### Apache Hadoop

```yaml
概要:
  - 分散処理フレームワーク
  - 大規模データ処理
  - バッチ処理

コンポーネント:
  HDFS:
    - 分散ファイルシステム
    - 高スループット
    - フォールトトレラント
  
  MapReduce:
    - Map処理（並列処理）
    - Reduce処理（集約）
    - バッチ指向
  
  YARN:
    - リソース管理
    - ジョブスケジューリング
    - クラスター管理

特徴:
  - 安定性高い
  - 大規模データ向き
  - Sparkより低速
  - ディスクベース処理
```

### Presto

```yaml
概要:
  - 分散SQLクエリエンジン
  - インタラクティブ分析
  - 複数データソース統合

特徴:
  高速:
    - インメモリ処理
    - パイプライン実行
    - 低レイテンシ
  
  柔軟性:
    - S3、HDFS、RDS
    - Hive、Cassandra
    - 異なるソースをJOIN

用途:
  - アドホック分析
  - インタラクティブクエリ
  - BI/ダッシュボード
  - データ探索

Athenaとの関係:
  - Athena = Presto on AWS
  - EMR Prestoはカスタマイズ可能
  - より複雑な処理対応
```

### Hive

```yaml
概要:
  - Hadoop上のデータウェアハウス
  - SQL（HiveQL）でデータ処理
  - MapReduceへ変換

特徴:
  メタストア:
    - テーブル定義
    - スキーマ情報
    - Glue Data Catalog使用可能
  
  SQL変換:
    - HiveQL → MapReduce/Tez/Spark
    - 複雑なSQLサポート
  
  バッチ処理:
    - 大規模データ
    - レイテンシ高め
    - リアルタイム向きでない

Glue Data Catalog統合:
  - メタストアとして使用
  - Athenaとメタデータ共有
  - 統合管理
```

### EMRFSとS3

```yaml
EMRFS:
  概要:
    - S3をHadoopファイルシステムとして使用
    - s3://プロトコル
    - EMR最適化
  
  メリット:
    - クラスター外永続化
    - コスト削減
    - データ共有
    - 耐久性（S3の99.999999999%）
  
  機能:
    - 一貫性ビュー
    - 暗号化（SSE-S3/KMS/CSE）
    - IAMロール統合

使い分け:
  HDFS:
    - 中間データ
    - 頻繁アクセス
    - 高スループット
  
  S3（EMRFS）:
    - 入力データ
    - 最終結果
    - 長期保存
    - クラスター間共有
```

### ステップ

```yaml
概念:
  - クラスター上で実行する処理単位
  - ジョブ実行の基本単位
  - 複数ステップの連続実行可能

ステップタイプ:
  Spark Job:
    - spark-submit
    - PySpark/Scala
  
  Hadoop Streaming:
    - MapReduceジョブ
  
  Hive Script:
    - HiveQL実行
  
  Custom JAR:
    - Javaアプリケーション
  
  コマンドランナー:
    - シェルコマンド
    - スクリプト実行

実行モード:
  CONTINUE:
    - 失敗しても続行
    - 後続ステップ実行
  
  TERMINATE_CLUSTER:
    - 失敗時にクラスター終了
    - 推奨設定
  
  CANCEL_AND_WAIT:
    - 失敗時に待機
    - 手動介入可能
```

### Auto Scaling

```yaml
概要:
  - ノード数自動調整
  - コスト最適化
  - パフォーマンス維持

スケーリング対象:
  - Core Node（慎重に）
  - Task Node（推奨）

メトリクス:
  YARNMemoryAvailablePercentage:
    - メモリ使用率
    - <15% → スケールアウト
  
  ContainerPendingRatio:
    - 待機コンテナ比率
    - >0.75 → スケールアウト
  
  AppsRunning:
    - 実行中アプリ数

カスタムルール:
  - CloudWatch Metrics
  - 時間ベース
  - 負荷ベース

制約:
  Core Node:
    - HDFSデータ保存
    - スケールイン時データ移動必要
    - 慎重な設定
  
  Task Node:
    - データ保存なし
    - 自由にスケール
    - Spot Instance最適
```

### セキュリティ

```yaml
暗号化:
  保管時:
    - HDFS暗号化
    - S3暗号化（SSE-S3/KMS）
    - EBS暗号化
    - LUKS暗号化
  
  転送中:
    - TLS/SSL（ノード間）
    - アプリケーション内通信暗号化
    - EMRFS S3通信（HTTPS）

認証:
  Kerberos:
    - Active Directory統合
    - クラスターレベル認証
    - アプリケーション認証
  
  LDAP:
    - Hue、Presto統合
    - ユーザー管理

IAM:
  サービスロール:
    - EMR自身の権限
    - EC2、S3アクセス
  
  EC2インスタンスプロファイル:
    - EMRインスタンス権限
    - S3、DynamoDB等アクセス
  
  ステップ実行ロール:
    - ステップ単位の権限

Lake Formation:
  - 細かいアクセス制御
  - テーブル・列レベル
  - Spark/Hive統合

ネットワーク:
  VPC:
    - プライベートサブネット
    - セキュリティグループ
    - NATゲートウェイ
  
  インターフェースVPCエンドポイント:
    - プライベート通信
    - パブリックIP不要
```

### まとめ

**EMRの重要ポイント:**
- マネージドHadoop/Sparkクラスター
- 複数フレームワーク対応（Spark、Hadoop、Presto、Hive）
- EMRFS でS3直接アクセス
- Spot Instanceで大幅コスト削減
- ステップ実行で自動化
- Auto Scalingで最適化
- EMR Serverlessでサーバーレス実行
- Glue Data Catalog統合
- EC2料金 + EMR料金（約25%追加）
