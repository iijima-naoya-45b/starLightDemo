## AWS CLI コマンド

### データセット管理

```bash
# データセット一覧
aws quicksight list-data-sets \
  --aws-account-id 123456789012

# データセット詳細
aws quicksight describe-data-set \
  --aws-account-id 123456789012 \
  --data-set-id your-dataset-id

# データセット作成（Athena）
aws quicksight create-data-set \
  --aws-account-id 123456789012 \
  --data-set-id sales-analysis \
  --name "Sales Analysis" \
  --physical-table-map '{
    "sales-table": {
      "RelationalTable": {
        "DataSourceArn": "arn:aws:quicksight:us-east-1:123456789012:datasource/athena-datasource",
        "Schema": "default",
        "Name": "sales_data",
        "InputColumns": [
          {"Name": "order_id", "Type": "STRING"},
          {"Name": "order_date", "Type": "DATETIME"},
          {"Name": "customer_id", "Type": "STRING"},
          {"Name": "product_id", "Type": "STRING"},
          {"Name": "sales_amount", "Type": "DECIMAL"}
        ]
      }
    }
  }' \
  --import-mode SPICE

# データセット削除
aws quicksight delete-data-set \
  --aws-account-id 123456789012 \
  --data-set-id your-dataset-id
```

### SPICE リフレッシュ

```bash
# SPICE リフレッシュ開始
INGESTION_ID=$(date +%s)
aws quicksight create-ingestion \
  --aws-account-id 123456789012 \
  --data-set-id your-dataset-id \
  --ingestion-id "ingestion-${INGESTION_ID}"

# リフレッシュ状態確認
aws quicksight describe-ingestion \
  --aws-account-id 123456789012 \
  --data-set-id your-dataset-id \
  --ingestion-id "ingestion-${INGESTION_ID}"

# リフレッシュ履歴
aws quicksight list-ingestions \
  --aws-account-id 123456789012 \
  --data-set-id your-dataset-id

# リフレッシュキャンセル
aws quicksight cancel-ingestion \
  --aws-account-id 123456789012 \
  --data-set-id your-dataset-id \
  --ingestion-id "ingestion-${INGESTION_ID}"
```

### ダッシュボード管理

```bash
# ダッシュボード一覧
aws quicksight list-dashboards \
  --aws-account-id 123456789012

# ダッシュボード詳細
aws quicksight describe-dashboard \
  --aws-account-id 123456789012 \
  --dashboard-id your-dashboard-id

# ダッシュボード公開
aws quicksight update-dashboard-published-version \
  --aws-account-id 123456789012 \
  --dashboard-id your-dashboard-id \
  --version-number 1

# ダッシュボード権限付与
aws quicksight update-dashboard-permissions \
  --aws-account-id 123456789012 \
  --dashboard-id your-dashboard-id \
  --grant-permissions '[
    {
      "Principal": "arn:aws:quicksight:us-east-1:123456789012:user/default/user-name",
      "Actions": [
        "quicksight:DescribeDashboard",
        "quicksight:ListDashboardVersions",
        "quicksight:QueryDashboard"
      ]
    }
  ]'

# ダッシュボード削除
aws quicksight delete-dashboard \
  --aws-account-id 123456789012 \
  --dashboard-id your-dashboard-id
```

### ユーザー管理

```bash
# ユーザー一覧
aws quicksight list-users \
  --aws-account-id 123456789012 \
  --namespace default

# ユーザー作成
aws quicksight register-user \
  --aws-account-id 123456789012 \
  --namespace default \
  --identity-type IAM \
  --iam-arn "arn:aws:iam::123456789012:user/john-doe" \
  --user-role AUTHOR \
  --email "john.doe@example.com" \
  --user-name "john-doe"

aws quicksight describe-user \
  --aws-account-id 123456789012 \
  --namespace default \
  --user-name "john-doe"

# ユーザー削除
aws quicksight delete-user \
  --aws-account-id 123456789012 \
  --namespace default \
  --user-name "john-doe"
```

### 埋め込みURL生成

```bash
# 登録ユーザー用埋め込みURL
aws quicksight generate-embed-url-for-registered-user \
  --aws-account-id 123456789012 \
  --session-lifetime-in-minutes 600 \
  --user-arn "arn:aws:quicksight:us-east-1:123456789012:user/default/user-name" \
  --experience-configuration '{
    "Dashboard": {
      "InitialDashboardId": "your-dashboard-id"
    }
  }' \
  --allowed-domains '["https://your-domain.com"]'

# 匿名ユーザー用埋め込みURL（QuickSight Q）
aws quicksight generate-embed-url-for-anonymous-user \
  --aws-account-id 123456789012 \
  --namespace default \
  --session-lifetime-in-minutes 600 \
  --authorized-resource-arns '["arn:aws:quicksight:us-east-1:123456789012:dashboard/your-dashboard-id"]' \
  --experience-configuration '{
    "Dashboard": {
      "InitialDashboardId": "your-dashboard-id"
    }
  }'
```

### 行レベルセキュリティ（RLS）

```yaml
設計:
  マッピング方式:
    CSV方式:
      - シンプル
      - 静的ルール
      - 小規模向き
    
    データベース方式:
      - 動的ルール
      - 複雑な条件
      - 大規模向き

実装:
  CSV例:
    # rls_rules.csv
    UserName,Region,Department
    alice@example.com,East,Sales
    bob@example.com,West,Sales
    charlie@example.com,*,Management
  
  SQL例:
    -- RLS テーブル
    CREATE TABLE rls_mapping (
      user_email VARCHAR(255),
      region VARCHAR(50),
      department VARCHAR(50)
    );
    
    -- データセットフィルター
    WHERE region IN (
      SELECT region 
      FROM rls_mapping 
      WHERE user_email = '${currentUserEmail}'
    )

テスト:
  - 各ユーザーでログイン確認
  - データフィルター動作検証
  - 権限境界テスト
  - パフォーマンステスト

注意点:
  - ユーザー名の一致確認
  - 大文字小文字区別
  - ワイルドカード（*）活用
  - パフォーマンス影響考慮
```

### 計算フィールド

```yaml
パフォーマンス:
  効率的:
    - シンプルな計算
    - 集計関数活用
    - テーブル計算
  
  非効率:
    - ネストの深い計算
    - 複雑な条件分岐
    - 行レベル計算（大量データ）

よくある計算:
  期間比較:
    # 前月比
    (sum({sales_this_month}) - sum({sales_last_month})) 
      / sum({sales_last_month}) * 100
    
    # 前年同月比（YoY）
    periodOverPeriodDifference(sum({sales}), {date}, YEAR, 1)
  
  累積:
    # 累積売上
    sum({sales}) OVER ([date ASC] ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW)
  
  移動平均:
    # 7日移動平均
    avg({sales}) OVER ([date ASC] ROWS BETWEEN 6 PRECEDING AND CURRENT ROW)
  
  ランキング:
    # 売上ランキング
    rank([{sales} DESC], [{date}])
  
  パーセンテージ:
    # 構成比
    sum({sales}) / sumOver(sum({sales}), [], PRE_AGG) * 100

デバッグ:
  - プレビューで確認
  - 小さいデータセットでテスト
  - エラーメッセージ確認
  - 段階的に構築
```

### トラブルシューティング

```yaml
よくある問題:

1. SPICE リフレッシュ失敗:
   原因:
     - データソース接続エラー
     - タイムアウト
     - スキーマ変更
     - 容量不足
   
   対処:
     - データソース接続確認
     - タイムアウト設定延長
     - スキーマ同期
     - SPICE容量追加

2. ダッシュボード表示遅延:
   原因:
     - 直接クエリモード
     - 複雑な計算
     - 大量ビジュアル
   
   対処:
     - SPICEモード使用
     - 計算最適化
     - ビジュアル数削減
     - データ事前集計

3. RLS動作しない:
   原因:
     - ユーザー名不一致
     - ルール設定ミス
     - キャッシュ
   
   対処:
     - ユーザー名確認
     - RLSルール再確認
     - ダッシュボード再公開

4. 埋め込みエラー:
   原因:
     - CORS設定
     - URL有効期限
     - ドメイン許可リスト
     - ユーザー権限
   
   対処:
     - AllowedDomains設定確認
     - URL再生成
     - ユーザー権限確認

5. データセット作成失敗:
   原因:
     - データソース権限
     - SQL文法エラー
     - タイムアウト
   
   対処:
     - IAM権限確認
     - SQL検証
     - クエリ簡素化
```
